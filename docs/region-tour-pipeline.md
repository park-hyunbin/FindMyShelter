# 지역별 3D 임장

메인에서 오포 임장에 바로 입장합니다. 지역을 검색하거나 `?region=songpa`를 열면 가락동부센트레빌로 이동합니다. `ShelterHome`은 선택한 구역의 `OpoTour`를 열고 필요한 건물 조각·DEM·환경·POI만 요청합니다. 지역 전환 시 이전 렌더러·GPU 자원·이벤트·로딩 요청을 정리합니다. `/polygons`는 건물 자료 검증 화면입니다.

## 현재 지역

- 오포: 기존 건물 214개, 주변 OSM 건물, DEM, 도로, 녹지, 수계, POI, 단지 도로·시설·공원 경로·위성영상.
- 송파는 가락동부센트레빌 101~105동, 송파대로32길의 눈높이 시작점, 지도상 단지 경계, 8m 간격 실외 일조 표본을 제공합니다. 반경 600m 건물 표본 752개와 GEDTM30 격자 11,025점, 주변 OSM 도로·녹지·장소를 사용합니다. 높이 미확인 309개는 그대로 NULL입니다. 주동 형상과 동 번호는 건물 표본을 사용했습니다. OSM의 103·104동 표기는 해당 표본과 차이가 있습니다. 경계는 OSM 주거 영역이며, 출입구·내부 보행로·상세 외관은 추가 확인이 필요합니다. [서울시 단지 정보](https://openapt.seoul.go.kr/openApt/index.do?aptCode=A13816002) · [OSM 경계](https://www.openstreetmap.org/way/1079940834) · [시작 도로](https://www.openstreetmap.org/way/169916279)

OSM 길은 일반화된 지도 선이며 정밀 도로 폭·보행 적합성·실제 교통 정보를 보장하지 않습니다. 송파의 운전 모드는 이 길 위의 탐색 연출입니다. DEM은 원본 약 30m를 25m 간격으로 보간한 표현이며 새로운 해상도를 만들지 않습니다.

## 지역 추가 순서

1. `data/config/buildings/{지역}.json`을 작성합니다. 안정적인 건물 ID·CRS·컬럼 매핑·중심·범위·출처를 지정합니다.
2. Python 건물 파이프라인으로 init → QGIS 검증 → build합니다. [건물 파이프라인](building-pipeline.md) 참조.
3. `node frontend/scripts/prepare-region.mjs --region {지역}`으로 해당 건물 원점에 정합되는 도로·녹지·물길·POI·DEM을 오프라인 생성합니다.
4. `frontend/components/data/regions.ts`에 지역명·검색어와 각 생성 파일 경로를 등록하고 화면을 검증합니다. 새 지역의 site/surrounding은 없으면 null입니다.

```sh
.venv/bin/python -m backend.pipeline build --config data/config/buildings/songpa.json
node frontend/scripts/prepare-region.mjs --region songpa
# 원본 변경 시에만 외부 지도/DEM을 다시 요청
node frontend/scripts/prepare-region.mjs --region songpa --refresh
```

`prepare-region`은 생성 파일이 있으면 외부 호출 없이 재사용합니다. 건물 원점과 DEM 원점이 다르면 중단하여 다른 동네 지형이 섞이지 않게 합니다. 도로·POI를 갱신하려면 --refresh를 사용합니다. 지역의 좌표를 변경했다면 반드시 함께 갱신해야 합니다. GEDTM30 출처와 라이선스는 terrain.json, OSM 출처·스냅샷은 environment.geojson에 남깁니다.

### 공통 생성과 개별 검수

송파 산책로의 작은 회색 포장 블록과 103·104동의 청색 창 아래 띠는 공개 사진의 외관을 참고해 공통 재질과 입체 창틀로 표현했다. 창호 위치와 블록 치수는 시각 모형의 근사다. 일조와 시야에는 GIS 윤곽과 높이로 만든 분석용 건물 체적을 사용한다. [103·104동과 산책로 사진](https://image.hogangnono.com/image/nowatermark/original/review/20251129172655_7a3aFmvY5EjhBA7uKX?q=100&s=720x180&t=outside)

방향별 시야 비교는 정문 접근로를 포함해 3D에서 서는 보행면 위 1.5m를 출발점으로 사용한다. 지형은 같은 모델 삼각면의 경계에서 최대 차폐각을 찾고, 단면 그래프는 최대 800m까지 50m 간격으로 표기한다. 건물 수집 범위는 관측점과 방향에 따라 달라지며 자료가 끝나는 거리 이후는 미판정이다. 정문 바닥의 실제 단차와 수목 차폐는 현장 확인 항목이다.

101~105동 1층은 사진에서 보이는 낮은 기단과 창 비율을 공통 외관 규칙으로 표현한다. 103동 앞 포장은 공개 사진과 GIS 건물 윤곽을 대조해 산책로에 이었다. 현관 모형은 건물 식별자와 외벽 방향에 맞춰 연결하고, 현관 위치·계단·문과 차양의 치수는 사진을 참고한 추정으로 표시한다. 104동 쪽 보행 포장은 산책로와 이어진다. 서울시 보행자 출입구 조사 원본에서 이 단지의 동별 출입구는 확인하지 못했다. [103·104동과 산책로 사진](https://image.hogangnono.com/image/nowatermark/original/review/20251129172655_7a3aFmvY5EjhBA7uKX?q=100&s=720x180&t=outside) · [서울시 보행자 출입구 조사](https://data.seoul.go.kr/dataList/OA-21699/S/1/datasetView.do?tab=A)

단지 산책로와 송이공원의 수목 위치는 기존 OSM·항공영상 표본을 사용한다. 공원 사진에 보이는 가지 높이와 수관 형태를 참고해 침엽수·활엽수 외관과 흙·포장 재질을 다듬었다. 개별 수종·키·잎의 밀도는 화면용 근사다. [송이공원 지상 사진](https://my-context.tistory.com/46)

송이공원 남쪽의 송이로·양재대로 횡단보도와 보도는 서울시 에스맵 오픈랩의 도로면·보도면·횡단보도 도형을 사용한다. 원본 식별자는 `songi-park-survey.json`에 기록한다. 입구 방향의 안내선은 횡단 도색과 보도면을 따르고, 도형 사이에 남는 짧은 접속부는 점선으로 표시한다. 484m와 474m는 종전과 같은 출발점·종점 사이의 OSM 경로 거리다. 턱과 경사로의 실제 상태와 신호 대기는 현장 확인 항목이다. - **데이터**에는 GIS의 건물 윤곽·높이·층수·용도, 표고, 차도·보행망, 녹지와 시설 범위를 기록합니다. 단지 내부 범위와 연결은 공식 자료와 항공 영상으로 대조하고 해석한 위치·폭에는 근사임을 기록합니다. 출처가 비어 있는 이동 연결과 높이·단차는 확인이 필요한 항목으로 남깁니다.
- **공통 3D**는 같은 데이터 형태에 같은 생성 규칙을 적용합니다. 단지의 진입로·보행로·포장·놀이터·횡단 위치는 `frontend/components/data/site-surfaces.ts`에 등록해 공통 렌더러로 그립니다. 송파 정문과 단지 안 보행로에 이 방식을 적용했습니다.
- 송파 일조표, 광선, 분포 지도 표본과 겨울 산책 시점은 포장과 보도가 반영된 3D 바닥 위 1.5m에서 시작합니다. 겨울 산책 중 같은 바닥 위 5cm의 판정이 눈높이와 다르면 발밑 판정을 함께 표시합니다. 13~17시의 10분 간격 표본은 직사광·그늘·미판정으로 묶어 보여줍니다. 두 표본 사이의 변화 시각과 실제 포장 높이는 현장 확인 항목입니다.
- 겨울 위성영상 대조에는 2025-12-22, 2026-01-06, 2026-02-20에 촬영된 동일한 Sentinel-2 10m 픽셀을 사용합니다. 픽셀마다 5×5 모델 표본과 중앙점을 3D 바닥 위 5cm에서 계산합니다. 영상의 RGB 표시값에는 바닥 재질, 수목과 대기의 영향이 남아 있습니다. 3D 산책은 별도로 눈높이 1.5m에서 계산하며 겨울 오후의 그림자 경계는 같은 날짜·시각의 지상 관찰이 필요합니다. [Copernicus Sentinel-2 제품 설명](https://documentation.dataspace.copernicus.eu/Data/Sentinel2.html) · [2026-02-20 원본 메타데이터](https://earth-search.aws.element84.com/v1/collections/sentinel-2-l2a/items/S2B_52SCG_20260220_0_L2A)
- 항공영상에서 읽은 단지 안 차량 포장면은 접하는 차도 가장자리의 모델 높이까지 부드럽게 이어집니다. 횡단 표시는 완성된 포장면의 높이를 따르며, 같은 위치에서 겹치는 차로 도색은 비웁니다. 포장 재질과 단차는 시각 모형의 근사입니다. [항공영상](https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer)

- 송파 생활시설 목록은 정문 접근로 눈높이 시점과 지도에 기록된 시설 좌표 사이의 EPSG:5186 평면 직선거리순입니다. 3D 지도에도 같은 기준점을 표시합니다. 이름표가 겹치면 선택한 장소와 거리 기준점, 가까운 장소 순으로 표시합니다. 시설의 출입구까지 실제 걷는 거리와 현재 영업 여부는 별도 확인이 필요합니다.
- 101~105동 외벽 바깥 표본은 GIS 윤곽에서 길이 6m 이상인 면 중 방향별로 가장 긴 면을 골라 만듭니다. 외벽 중앙에서 바깥으로 3m 떨어진 단지 안 실외 지점만 남기고, 진북 기준 외벽 방향에서 건물 표본의 첫 교차 거리를 계산합니다. 시야와 일조는 같은 바닥 위 1.5m에서 봅니다. 공개된 공급 141㎡·170㎡ 기본형에는 거실과 발코니가 보이며, 방위와 동·호수별 연결은 확인되지 않았습니다. - 공개 차선과 정지선은 실제로 그린 차도와 단지 차량 포장에 겹치는 부분만 표시합니다. 도색 높이는 그 지점의 포장 표면에서 구합니다. 송파에서는 화면에 투영한 도색 폭이 1픽셀에 못 미칠 때 투명도를 점진적으로 높여, 조감에서 얇은 선이 점처럼 튀지 않게 합니다. 도색 자료와 포장 윤곽 자료가 어긋나는 구간의 연결 여부는 현장에서 확인해야 합니다.

### 새 단지를 만드는 순서

1. **원본을 받아 버전을 고정한다.** 자료별 제공처·원본 ID·제작/촬영 기준일·수집일·좌표계·수직 기준·원본 해상도·허용 용도를 기록한다. GIS건물통합정보는 제공처에서 확인한 원본과 컬럼 정의서로 기존 송파 샘플의 필드 매핑과 권원을 대조한다. 원본은 변경 이력을 관리하고, QGIS는 단지 매칭 충돌이나 경계·출입구 같은 예외를 검수할 때 사용한다.
2. **공통 레이어를 같은 좌표계로 맞춰 생성한다.** 현재 EPSG:5186을 유지하고 높이 기준을 맞춘다. 원본 건물관리번호·건축물대장 식별자·GIS 피처 ID와 내부 건물 ID의 대응을 저장한다. 단지별 중심점을 그대로 건물 또는 출입구로 매칭하지 않는다. 도로와 시설에는 원본 ID·출입구·층위·보행 연결 여부를 붙인다.
3. **단지별 확인 사항을 구조화해서 추가한다.** 단지 ID에 경계·동 번호·정문·후문·내부 길·검증된 시설·시작 시점·시범 경로를 연결한다. 각 기록에는 출처와 확인일, 배치도·현장 자료로 확인한 항목과 추정 항목을 남긴다. 새 원본이 오면 기존 검수 결과와 달라진 지점만 다시 대조한다.
4. **브라우저용으로 미리 만든다.** 초기에는 기존 지역 매니페스트와 해시가 붙은 건물 조각을 재사용한다. 서울 확대 시 단지 주변 공통 조각을 공간 타일로 공유하고, 가까운 구역의 상세 모형을 우선 요청한다. 일조·시야는 현재 화면 밖에서도 그림자나 시야를 가릴 수 있는 건물과 지형을 포함해 계산 범위를 별도로 잡는다. 보행은 목적지까지 이어지는 경로 구역을 읽는다. 시범 경로는 배포 전에 생성하고, 현장 대조가 끝난 범위를 명시한다.
5. **공개본을 검사하고 갱신한다.** 출처 표기와 가공·재배포 가능 범위를 원본과 산출물 단위로 확인한다. 해외 클라우드에 올릴 정밀 자료는 제공기관 조건과 배포 범위를 먼저 확인한다. OSM은 출처와 ODbL 적용 관계를 기록한다. 영상·사진은 권한이 확인된 자료로 텍스처를 만든다. 건물 누락·ID 중복·끊긴 경로·지형 경계의 높이 차이를 검사하고, 통과한 새 버전만 공개한다. ### 공개 범위와 확장 검증

- **기본 3D**는 단지 모든 주동의 배치, 인근 건물·도로·녹지·물길과 지형을 표현한다. 화면에서 추정 외관과 확인된 주요 시설을 식별할 수 있게 한다.
- **일조·언덕길·보행 경로**는 계산 가능한 구간별로 제공한다. 일조에는 날짜·시간과 지면 기준 관측 높이, 언덕길에는 표고 출처·표본 간격과 오르막을 산정한 구간 길이, 보행 경로에는 실제로 대조한 출입구·횡단·계단과 미확인 연결을 표시한다. 현장 촬영 시각을 아는 사진으로 대표 지점의 그림자를 대조한다.
- **송파 확장 검증**은 가락동부센트레빌에 이어 사진이 적은 인근 단지 한 곳을 같은 설정·파이프라인으로 만든다. 사진 자료가 부족해도 단지와 동네의 기본 3D가 생성되는지, 양쪽에서 같은 기준으로 검색·경로·일조를 비교할 수 있는지, 손으로 고친 항목 수와 검수 시간을 확인한다. 이 방식이 재현되면 송파의 다음 단지부터 적용한다.
- **서울 전역 운영**에서는 검색 결과에 기본 3D·보행·일조의 제공 상태를 표시한다. 아직 준비되지 않은 위치의 분석은 미제공으로 표시하고, 같은 구역의 데이터 조각을 인접 단지가 다시 사용하게 한다.
