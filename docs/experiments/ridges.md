# 능선 후보 실험 — 구현 전 검증 계획

등고선과 높이 자료에서 산등성이의 후보를 찾아보는 초기 실험 계획입니다.

[전체 문서 목차](../README.md) · [공개 3D에서 쓰는 지형](../planning/2026-11-21-seoul-pilot-validation.md#이웃-단지의-지형-높이-대조) · [지형 원본과 작업 순서](../../data/README.md#고도-dem-추가)

현재 등고선은 고도 등치선이며 능선이 아닙니다. 현재 프로젝트에는 능선 추출 결과가 없습니다.

## 1차: GRASS r.geomorphon

공식 문서: https://grass.osgeo.org/grass-stable/manuals/r.geomorphon.html

분석용 원래 90m DEM을 입력합니다. 화면용 쌍선형 보간 타일을 분석에 사용하지 않습니다.
분류값 3은 ridge, 2는 peak, 5는 spur입니다. 첫 실험에서는 ridge만 추출하고 나머지를 자동으로 합치지 않습니다.

- search: 3, 5, 9 셀을 비교 (90m 원본에서 약 270/450/810m 탐색 스케일)
- skip: 0
- flat: 1도 초기 실험값
- dist: 0
- `-m`을 쓰지 않으면 search/skip은 셀 단위입니다.
- 표고 단위가 확인되지 않았으므로 각도 기반 분류 역시 실험 후보로만 취급합니다.

출력 범위보다 최대 탐색 반경 이상 넓은 원본 DEM을 읽어 경계효과를 줄입니다. 건물 주변 1km 결과를 만들려면 최소 810m 이상의 추가 문맥이 필요합니다. 원본 DEM에서 충분한 문맥을 잘라내고 분류 후 관심 범위를 추출합니다.

QGIS 처리 흐름:
1. `r.geomorphon`으로 지형 분류 GeoTIFF 생성
2. 래스터 계산기로 ridge=3인 셀만 남김
3. 분류 셀 영역을 먼저 원본 지형·등고선과 수기 대조
4. 선 표현이 필요할 때만 `r.thin` → `r.to.vect`(line) 후 GeoJSON 저장
5. 민트색 점선 `능선 후보 · 알고리즘 추출 · 검증 전`으로 표시

래스터 분류 결과가 단절된 경우 임의로 이어서 용맥을 만들지 않습니다. 꼭짓점·분기점·연결성·탐색 반경별 안정성을 비교합니다. 선 표현은 후보 셀의 중심을 잇는 표현이지 측량된 능선 중심선이 아닙니다.

현재 실행 환경: GRASS CLI 및 r.geomorphon 실행 파일은 확인되지 않았습니다. QGIS 앱과 GRASS 제공자 플러그인은 있으나 실제 알고리즘 실행 가능 여부는 별도입니다. 설치·실행 전에는 결과가 있다고 표시하지 않습니다.

## 후속: WhiteboxTools FindRidges

개발자 공식 매뉴얼: https://jblindsay.github.io/wbt_book/available_tools/geomorphometric_analysis.html

FindRidges의 기본 출력은 래스터이며 `line_thin=True`는 한 셀 폭으로 가늘게 만드는 옵션입니다. 벡터 선이 바로 생성되는 것은 아닙니다.

r.geomorphon 결과의 대안 비교용입니다. 도구 버전·입력 DEM·파라미터·출력 형식과 thinning 적용 여부를 기록하고, 어느 도구의 선도 자동으로 용맥 확정선으로 취급하지 않습니다.

## 실폭도로

원본과 120개 샘플 도형은 보존합니다. 화면 기본 표시는 꺼짐이며 로컬 지도에서 필요할 때 켤 수 있습니다. 현재는 도로 폭 숫자·통행량 분석을 하지 않습니다.
