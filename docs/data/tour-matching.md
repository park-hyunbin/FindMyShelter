# 조건 맞춤 임장

첫 화면은 아파트 찾기로 열립니다. 지역·동네·단지명을 검색하고 매매·전세·월세 예산과 생활 조건을 적용합니다. 결과를 마을 지도의 이정표로 표시하고, 선택한 한 단지의 복도 유형·주차·실거래를 옆의 동네 수첩에 보여줍니다. 마을 지도는 탐험용 그림으로 실제 거리나 위치 관계를 나타내지 않습니다. **3D 마을 탐험**에서는 조건 입력 없이 오포·송파 중 한 곳을 고릅니다. 입장할 때 선택한 지역의 3D 데이터만 불러오고, 임장에서 조건 화면으로 돌아와도 같은 탭에서 입력값을 유지합니다.

직접 입력한 매매가는 현재 매물 비교에만 사용합니다. 입력값을 받지 않는 전월세의 현재 가격은 미확인입니다. 과거 계약 참고에서는 매매가 또는 보증금과 월세 상한을 적용합니다. 과거 계약이 예산 이내여도 현재 매물이 예산에 맞는다는 의미가 아닙니다. 예산과 매물가는 탭 화면 상태로만 유지하며 서버로 전송하지 않습니다.

송파와 오포 동네 엽서는 기존 GIS 주동 윤곽·높이 자료와 OpenStreetMap 단지 경계·길을 비스듬히 그린 일러스트입니다. 층 표시와 도로 폭은 화면 표현입니다. `.venv/bin/python backend/scripts/prepare_tour_postcard.py --region songpa` 또는 `--region opo`로 다시 생성할 수 있습니다.

첫 화면에는 [Animal Island UI 4.0.1](https://github.com/guokaigdg/animal-island-ui)의 Input, Button, Card, Checkbox, Tag, Image 및 NoData를 사용합니다. 검색과 GIS 데이터 적용은 프로젝트 쪽 코드가 담당합니다. UI 패키지와 관련 라이선스의 원문은 `frontend/public/licenses/`에 있고, 화면 하단에서 `/licenses/`로 열 수 있습니다.

## K-apt 자료 갱신

```sh
.venv/bin/python backend/scripts/prepare_tour_complexes.py \
  data/processed/complexes/kapt/20261113_단지_기본정보.csv --snapshot-date 2026-11-13
```

단지 코드 `A46492201`, `A13816002`로 각각 오포, 송파 행을 선택합니다. 앱에는 세대수·주차대수·복도 유형·놀이터 여부·충전시설 여부만 담습니다. 시설 수나 상태를 확인할 수 없는 항목은 NULL을 유지합니다. 전체 CSV나 연락처는 웹에 넣지 않습니다. [K-apt CSV 만들기](kapt-complexes.md)

## 실거래 CSV 갱신

직접 내려받은 매매·전월세 CSV를 `data/raw/transactions/molit/`에 날짜를 포함한 원본 이름으로 둡니다. 한 쌍은 같은 계약일 범위로 내려받습니다. 여러 달을 추가할 때는 앞 기간 종료일의 다음 날부터 조회해 날짜가 겹치거나 비지 않도록 합니다.

```sh
.venv/bin/python backend/scripts/prepare_tour_transactions.py
```

파일 이름으로 거래 유형을 나누고 CSV 내부의 계약일 범위로 짝을 맞춥니다. 같은 기간에 같은 유형 파일이 두 개 있거나 범위가 겹치거나 비면 기존 출력은 유지하고 중단합니다. 특정 파일만 선택하려면 `--sale`과 `--rent`를 기간별로 반복해 지정합니다.

주소·지번·단지명을 함께 확인해 선택한 두 단지의 계약만 추출합니다. 매매 해제 행을 제외하고 계약일·전용면적·가격만 화면에 사용합니다. 현재 2026-09-18~11-18 자료를 반영했으며, 오포는 매매 4건·전세 1건이고 송파는 기록이 없습니다. 기록 없음은 해당 파일·기간 기준입니다. 원본에는 더 많은 지역이 있지만 임장 화면이 준비된 두 단지를 대상으로 하며, 이 CSV 기반 요약은 로컬 검증용입니다.

[국토교통부 실거래가 자료제공](https://rt.molit.go.kr/pt/xls/xls.do)은 계약일 기준 CSV가 변경될 수 있으며 외부 공개용 통계에는 신고일 기준 공식통계를 쓰라고 안내합니다.
