# 도로·차선 데이터 기준과 공개 장면 점검

2026-11-22 기준으로 공개 Sites v129의 가락동부센트레빌 정문 접근로와 공통 도로 렌더러를 확인했다. 서울 10개 장면과 오포 1개 장면이 점검 범위다. 이 문서는 기존 렌더러에서 확인한 현상과 앞으로 도로 데이터를 생성하고 공개할 때 적용할 기준을 기록한다.

서울 25개 구의 원본을 내려받는 명령과 평면 대조 결과는 [서울 전역의 차선·차도 일괄 수집](seoul-road-bulk-sources.md)에 있다.

## 가락 정문에서 확인한 원인

- 2021년 서울시 차선 도형의 황색 실선 하나는 원본 길이가 30.8m다. 코드가 흰 줄 도형을 둘러싸는 사각형으로 약 5.6m를 지웠다. 남은 선에 차도 삼각면을 한 번 더 적용하자 도색 면적은 약 26%만 남았다. 지도에서 실제로 그릴 흰 줄의 외곽과 차선의 삭제 범위를 별개로 생성하는 데서 첫 번째 손실이 발생한다. [차선 자르기](../../frontend/components/opo-crosswalks.ts) · [노면표시 그리기](../../frontend/components/opo-streets.ts)
- 사진의 노랑·흰색 띠는 서울시 T-GIS의 이미지형 감속 표시 `16-003565`다. 옆 흰 줄은 로드뷰를 보고 별도로 그린 정문 표시다. 모델에서 두 도색 외곽은 겹치지 않고 약 0.22m 떨어지며, 축 방향은 약 85° 다르다. 반대쪽 원본 황색 실선 조각 1.7m 중 약 0.4m는 감속 표시 아래에 들어간다. 차선과 감속 표시를 따로 그리면서 서로의 앞뒤 관계는 검증하지 않았다. [정문 흰 줄 좌표](../../frontend/components/data/songpa-grounds.ts) · [서울시 감속 표시 원본](https://data.seoul.go.kr/dataList/OA-15541/S/1/datasetView.do)
- 서울 장면은 서울시 차도·보도 도형과 OSM 도로망을 섞어 도로 면을 만든다. 차도·보도는 단지 경계 주변의 거리 범위로 자르고, 차선 원본은 별도의 좌표 사각형으로 자른다. 차선은 어느 도로 구간·진행 방향·층위에 속하는지 연결하지 않은 채 그 지점에 있는 차도 삼각면에만 남긴다. 한 레코드의 일부가 차도 면 밖에 있으면 남은 조각만 표시된다. 범위 차이, 도로 폭 추정, 원본 간 위치 오차가 같은 방식으로 화면에 나타날 수 있다. [차도·보도 생성](../../backend/scripts/prepare_neighborhood_pavement.py) · [차선 추출](../../backend/scripts/prepare_songpa_road_markings.py)

이 사례에서 확인한 손실은 화면을 그리기 전 좌표 계산에서 재현됐다. 차선 생성 규칙을 바꿨던 이전 수정은 추정 차선을 없앴지만 이 자료 연결 과정은 남아 있었다.

## 횡단보도와 차선이 겹치는 처리

공통 렌더러는 차선 도형을 먼저 차도 삼각면에 붙인다. 횡단보도 사각형으로 차선을 미리 자르던 처리를 없애고, 화면에 올릴 흰 줄·감속 표시의 실제 도색 면이 같은 도로층에서 겹치는 곳만 차선에서 제외한다. 횡단 표시가 차도 밖으로 잘린 부분과 흰 줄 사이의 빈 곳에는 기존 차선이 이어진다. 같은 위치라도 높이가 다른 도로의 도색은 서로 차선을 지우지 않는다. [노면표시 그리기](../../frontend/components/opo-streets.ts) · [삼각면과 높이 대조](../../frontend/components/opo-surface-clip.ts)

같은 장면 자료를 두 렌더러에 넣어 생성된 도색 삼각면을 비교했다. 가락 정문 황색 실선(원본 30.81m) 주변의 도색 면적은 약 0.93㎡에서 1.41㎡로 늘었다. 원본 선 전체에 14cm 폭으로 칠하면 약 4.31㎡이므로, 남은 손실에는 차도면 누락 대조가 필요하다. 서울 10개 장면 모두에서 황색 차선 도색 면적이 증가했다. 장면별 증가량은 약 2~18.6㎡이며 생활권이 겹치는 장면은 같은 위치를 중복 집계한다. 오포를 포함한 11개 장면의 로딩과 도색 삼각면 생성을 검사했다.

단지 중심 150m 안으로 좁혀도 가락동부센트레빌은 1,345m 중 352m, 래미안길음1차는 660m 중 265m가 차도에 붙지 않았다. 잠실 르엘은 같은 범위에서 2,241m 중 59m였다. 단지 가까이에도 문제가 있고, 단지별로 정도가 다르다.

길이와 건수는 장면별 집계라 생활권이 겹치면 같은 위치가 중복된다. 출처가 오래되어 지워진 차선, 차도 자료가 비어 있는 곳, 실제로 잘못 잘린 차선의 비율은 이 검사만으로 구분할 수 없다. 이 수치는 원본과 최종 3D가 어디에서 서로 맞지 않는지 후보를 찾는 데 사용한다.

## 차도와 차선을 같은 범위로 내보내기

공개 장면은 하나의 T-GIS 스냅샷에서 차도·보도 폴리곤과 차선·정지선을 함께 읽는다. 원본 선형을 차도면에 연결하고, 입체도로 주변에는 층위와 단면을 추가로 검증한다. 도로 중심선은 이동과 포장 대체에 쓴다. 점선은 장면 경계에서 잘려도 원본 선형의 시작점을 기준으로 같은 간격을 유지한다. 화면에서 서로 다른 스냅샷이 동시에 들어오면 차선을 숨긴다.

같은 렌더러로 서울 10개 장면의 실제 차도·차선 메시 생성을 확인했다. 가락 정문의 실선 주변에 그려진 황색 도색 면적은 이전 약 1.41㎡에서 약 4.02㎡로 늘었다. 30.81m에 14cm 폭을 전부 칠했을 때의 면적은 약 4.31㎡다. 횡단보도와 감속 표시는 각각의 조사 자료와 날짜를 기록하고, 차도 위에 보이는 도색 면을 기준으로 겹치는 부분을 처리한다.

```powershell
uv run --with numpy --with pyshp --with shapely --with pyproj --with openpyxl python backend/scripts/prepare_seoul_road_windows.py ../road-source-cache/tgis-live-index.sqlite ../road-source-cache/tgis-structure-evidence.sqlite --bridges ../road-source-cache/N1A_A0070000.zip --grade-separation ../road-source-cache/N1A_A0090000.zip --national-links ../road-source-cache/national-road-links-2026-11-11.zip --snapshot ../road-source-cache/tgis-live-seoul.sqlite --output ../road-source-cache/staged-regions
```

`reconcile_seoul_marking_links.py`로 먼저 동일 인덱스의 입체도로 근거를 만든다. 배치는 장면별 보류 사유와 길이를 출력한다. 검사한 `pavement.json`과 `road-markings.json`을 장면별로 함께 반영한다. [일괄 생성 코드](../../backend/scripts/prepare_seoul_road_windows.py)

## 노면표시 종류와 색상

살곶이길에서 흰색으로 표시되던 `11-0000129659`, `11-0000168795`는 서울시 원본에 노란색 주정차 금지선으로 등록되어 있다. 기존 변환은 여러 노면표시를 같은 흰색으로 묶고 자전거도로 표시를 버스전용차로와 같은 청색으로 처리했다. 흰색 주행유도선과 가변주차 구획도 이 교차로 주변에 별도로 등록되어 있다. [서울시 차선 자료](https://data.seoul.go.kr/dataList/OA-15537/S/1/datasetView.do) · [T-GIS 지도 표시 코드](https://tgis.eseoul.go.kr/js/map/MapFacilityMng.js)

종류 `A058_KND_CDE`와 세부 유형 `A058_KND2_CDE`를 함께 해석해 색상과 실선·점선을 고른다. 예를 들어 세부 코드 `002`는 주정차 금지선이면 노란 복선이고, 주행유도선이면 분홍 실선이며, 자전거횡단도이면 흰색 점선이다. 지상과 고가 모두 이 규칙을 사용한다. 복선을 원본에서 한 기준선으로 제공하는 경우 두 줄 간격은 모델 값으로 렌더링한다. 지상 배치는 인덱스와 같은 스냅샷의 식별자와 해시를 확인하고 알 수 없는 코드 조합을 보류 길이에 기록한다. [원본 코드 변환](../../backend/scripts/prepare_songpa_road_markings.py)

공개 서울 장면 10곳에서 지상 선형 5,729건과 고가 선형 4건의 색상 또는 도색 패턴을 바로잡았다. 겹치는 장면에 나온 같은 도형이 집계에 포함된다. 전후 원본 선형 좌표와 차도·보도 경계를 대조했다. 살곶이길에서 추적한 네 노란 선은 최종 3D 도색 면적을 유지했고, 정지선과 주행유도선은 원본 유형대로 흰색으로 그려졌다.

### 교차로의 흰색 주행유도선

살곶이길 교차로의 흰 선 `11-0000340902`, `11-0000340903`은 서울시 원본에서 회전 경로를 따르는 주행유도선이다. 같은 흰색 점선으로 분류되던 일반 차선의 도색 4m와 빈 간격 4.5m를 적용하면서 교차로 안에 긴 흰 줄이 떨어져 보였다.

서울시의 종류 `012`, 세부 코드 `001`에 별도 도색 간격을 적용한다. 유도선 표준도 525번은 도색과 빈 간격을 같게 하며 각각 0.5~1m를 제시한다. 개별 도색 길이를 알 수 없는 경우 범위 중간인 0.75m를 양쪽에 쓴다. 원본 선의 굽은 점을 남겨 거리 변화를 줄이고, 장면 경계에서 잘려도 원본 시작점으로부터 잰 거리로 같은 점선 간격을 유지한다. [도로교통법 시행규칙 별표 6, 표지 525](https://www.law.go.kr/LSW/flDownload.do?flSeq=168508797)

서울 공개 장면 10곳에서 적용한 지상 선형은 941건이며, 장면 중복을 제외한 시설 관리번호는 648개다. 렌더링 검사는 일반 차선의 도색 간격이 유지되는지와 유도선이 도색·빈 간격 중간에서 잘려도 배열이 이어지는지를 확인한다. [유도선 간격 검수](../../frontend/scripts/audit-road-cross-sections.cjs)

## 교량 상판과 하부 차도

교량 끝을 드나드는 경로나 교량 밑을 가로지르는 길이 있으면, 평면 투영에서 하나의 조사 차도 폴리곤에 겹칠 수 있다. 예전에는 교량을 부분적으로 가로지르는 지상 진행축 하나가 잡혀도 조사 폴리곤 전체를 지상 포장에 유지했다. 마포대교에서는 접속부의 약 9m 겹침으로 상판과 겹친 조사 면 약 1만 1천㎡가 지상 후보로 남았다. 강변북로 본선과 하부 연결로에는 별도 지상 차도 도형이 있었다.

같은 시설의 S-Map 외곽이 잘라내기 전 T-GIS 차도 원본 면적의 75% 이상을 덮고, 국가 표준노드링크의 고가·교량 구간이 그 외곽 안에서 최소 60m 겹치며 그 길이의 80% 이상이 원본 차도 안에 있을 때 상판 소유를 확인한다. 후보 시설이 하나인 경우 조사 차도에서 해당 상판과 겹치는 부분을 지상 포장에서 뺀다. 다른 차도 원본은 각자의 근거로 처리한다. [S-Map 도로교 외곽](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1A_A0070000.zip) · [국가 표준노드링크](https://www.its.go.kr/nodelink/nodelinkRef) · [차도 배치 코드](../../backend/scripts/prepare_seoul_road_windows.py)

상판 소유를 확인한 차도의 UFID를 시설에 기록한다. 고가 도색을 다시 만들 때 `prepare_seoul_elevated_markings.py --road-index`에 같은 T-GIS 스냅샷으로 만든 차선 인덱스를 전달한다. 그 상판에 단일 차도면으로 연결된 표시 중 고가 진행축과 나란하고 분리대, 지상 차도, 보도 또는 기존 고가 도색에 겹치지 않는 부분을 복원한다. 원본 관리번호, 도색 유형과 점선의 시작 거리를 사용한다. [고가 차선 추출기](../../backend/scripts/prepare_seoul_elevated_markings.py)

마포대교 한쪽 상판을 공유하는 두 장면에서 원본 관리번호 9개의 도색을 복원했다. 두 장면에 겹쳐 나온 원본을 한 번만 세면 중앙선 약 412m와 흰색 차선 약 2.05km다. 상판 진행축의 검사 위치에서 지상 포장이 중복으로 그려지던 경우가 제거됐고 아래를 가로지르는 강변북로와 연결로의 포장은 같은 위치에서 유지됐다. 하부 차도를 약 2m 간격으로 대조한 표본에는 조사 외곽과 양쪽 경계가 0.5m 넘게 다른 곳이 남아 있다. 반대편 상판의 중앙선 약 333m도 T-GIS 차도와 S-Map 외곽 차이로 보류됐다.

## 입체도로 주변의 지상 차선

기존 배치는 도색에서 16m 이내에 고가·교량·지하차도·터널 링크가 하나라도 있으면 서울시 지상 차선도 잘라냈다. 차도 옆의 입체도로까지 이 조건에 걸리면서 도색 중간이 비었다.

서울시 차선 `EVE_CDE=001`과 같은 조사의 지상 차도 경계를 먼저 확인한다. 그다음 국가교통정보센터 표준노드링크의 지상 도로 `ROAD_TYPE=000`를 대조한다. 최대 4m 간격의 표본에서 차선은 도로 진행축과 나란하고 정지선은 가로질러야 한다. 도색 표본과 중심선 투영점을 잇는 구간도 지상 차도 면에 완전히 포함되어야 한다. 복원할 수 있는 조각은 같은 원본 선의 인접 구간에 연결해 기존 도색 방향과 점선 간격을 유지한다. 차도와 보도 경계가 끊기는 구간, 여러 중심선 사이에서 구분이 어려운 구간은 보류한다. 검수 DB와 차선 인덱스, 표준노드링크 원본 버전은 해시로 대조한다. [서울시 차선 원본](https://data.seoul.go.kr/dataList/OA-15537/S/1/datasetView.do) · [표준노드링크 자료실](https://www.its.go.kr/nodelink/nodelinkRef)

공개 서울 장면 10개에 적용해 8개 장면에서 원본 지상 노면표시를 복원했다. 복원된 원본 선형은 장면별 합계 29.1km다. 이 길이는 겹치는 장면과 점선의 빈 간격을 포함한다. 횡단보도 검수 6,191건과 지상·고가 차도폭 검수값은 이전 배포와 일치했다. 분리대를 사이에 둔 다른 차도의 중심선, 차도와 직각인 일반 차선, 끊긴 차도 경계는 회귀 검사에서 차단한다. [지상 차선 회귀 검사](../../backend/scripts/test_seoul_road_windows.py)

후속 검수에서 입체도로와 가까운 원본을 한 덩어리로 판정하면 확인된 구간까지 함께 빠지는 것을 확인했다. 원본 선형을 실제 지상 포장에 먼저 자르고, 최대 4m 간격의 표준노드링크 확인 결과를 통과한 연속 구간에만 적용한다. 차도가 실제로 끊기는 곳을 건너뛰어 연결할 수 없으며 정지선은 일부만 복원하지 않는다. `prepare_seoul_road_windows.py --lanes-only`로 같은 스냅샷의 기존 포장을 사용해 일괄 갱신할 수 있다. 공개 장면 10곳을 비교한 결과 기존 중앙선의 위치를 유지하면서 장면 중복을 뺀 지상 중앙선 1.23km를 추가로 확인했다. [지상 차선 추출기](../../backend/scripts/prepare_seoul_road_windows.py)

중앙선은 양쪽 진행 방향의 경계에 있으므로, 같은 도로의 양방향 표준 링크가 1m 이내의 거리 차이로 함께 잡힐 수 있다. 예전에는 이 상황에서 도색을 보류했다. 이제 원본 중앙선이 같은 실측 차도 안에서 도로명과 노선번호가 같은 링크 두 개 사이에 있고, 두 링크의 진행 방향이 반대일 때 양방향 차도로 판정한다. 비슷한 거리의 평행 입체 링크가 있거나 검사 구간이 S-Map 교량·고가·지하차도 외곽을 가로지르면 보류한다. 이 규칙은 T-GIS 중앙선 `001`에 적용한다. 포장을 유지하는 `--lanes-only` 실행에도 기존 포장에 기록된 두 S-Map 아카이브를 전달해 같은 층위 근거를 사용한다. [표준노드링크](https://www.its.go.kr/nodelink/nodelinkRef) · [S-Map 공개자료](https://openlab.eseoul.go.kr/) · [판정 코드](../../backend/scripts/prepare_seoul_road_windows.py)

원본의 지상 코드가 붙은 중앙선은 한 S-Map 고가 외곽이 원본 길이의 98% 이상을 덮고 조사된 지상 차도와 겹치는 부분이 1cm 이하여야 고가 후보가 된다. 다른 고가와 공유하는 외곽, 분리대와 이미 수록된 고가 중앙선을 제외한다. 남은 구간에서는 같은 고가를 사용하는 도로망의 진행축까지 차도면이 이어지는지, 같은 외곽에서 같은 방향의 지상 도로가 경쟁하는지 검사한다. 최종 결과에는 원본 관리번호와 지상 층위 코드 `sourceLevel=001`을 남긴다. 공개 장면에서 이 조건을 통과한 원본은 6개 관리번호로, 중복을 뺀 선형 길이는 1.53km다. 층위가 확인되지 않은 부분은 후속 조사 대상으로 남긴다. [고가 차선 추출기](../../backend/scripts/prepare_seoul_elevated_markings.py) · [서울 전역의 중앙선 검사](seoul-road-bulk-sources.md#서울-전역의-중앙선-검사)

원본이 여러 고가나 지상 접근로를 지나면 각각의 고가에서도 위의 98% 기준에 못 미칠 수 있다. 이때 원본을 조사된 고가 차도에 자르고 지상 차도·보도, 다른 고가와 공유하는 외곽, 분리대를 먼저 뺀다. 고가로 이미 기록된 중앙선에서 0.5m 이내는 기존 도색을 우선한다. 같은 고가 차도에 연결된 진행축이 최대 4m 간격으로 이어지고, 같은 고가 외곽에 평행한 지상 진행축이 경쟁하지 않는 8m 이상의 연속 구간을 추가로 연결한다. 지상 코드는 출처로 남기고 원본 좌표와 점선의 시작 거리를 사용한다. [고가 차선 추출기](../../backend/scripts/prepare_seoul_elevated_markings.py)

## 지상도로와 고가도로 검사

천호대로25길의 한 단면에서는 서울시 지상 차도 경계가 약 7m인데 이전 장면의 포장 메시가 고가도로 쪽으로 41.66m까지 이어졌다. 주변에 고가 중심선이 있다는 이유로 일반 차도와 보도까지 고가의 추정 높이를 적용했고, 추정 포장이 서로 다른 층과 차도의 경계를 연결했다.

서울시 1:1,000 도로교와 고가차도 도형을 별도로 읽어 교량 태그가 있는 도로망과 교차 검증한다. 원본 도형의 식별자와 도로 ID, 아카이브 날짜와 해시를 함께 저장한다. 서울 10개 장면에 중복을 빼고 29개 시설이 연결됐다. 해당 평면 도형은 교량 전용 표면으로 그리며, 그 아래를 통과하는 도로망이 T-GIS 차도 면에 연결되는 경우 그 지상 면을 보존한다. 높이는 도로망으로 추정한 값이고, 두 층의 실제 높이 차나 지하차도 형상은 별도 자료가 필요하다. [서울시 도로교 도형](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1A_A0070000.zip) · [서울시 입체교차부 도형](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1A_A0090000.zip)

차선과 횡단 표시를 지상 포장에 붙이는 과정에서 교량 표면을 후보로 사용하지 않는다. 서울시 차도와 보도가 함께 확보된 장면에서는 도로 중심선 폭으로 횡단보도 진입 보도를 임의로 그리지 않는다. 잠실 올림픽로의 약 3m 안전지대는 서울시 원본에 도형이 있어 유지한다.

도형의 삼각면과 단면을 직접 교차해 25cm 간격 샘플이 놓치던 포장 사이 틈을 계산한다. 계산 정밀도에 따른 2mm 미만 이음새를 연결하고, 원본에 기록된 교통섬을 차도에서 뺀다. 도로 양쪽 경계의 오차가 모두 0.5m 이내인 비율은 아래와 같다. 도형을 층별로 분리하면서 비교 가능한 지상 표본 수도 달라졌다.

천호대로25길에서 41m 이상 이어졌던 네 단면은 분리 후 모두 지상 차도 양쪽 경계에 0.5m 이내로 맞았다. 가락 정문의 황색 중앙선 주변 다섯 단면은 위 표의 수정 후 폭을 유지했다. 원본에 좌우 경계가 없는 표본과 조사 날짜가 다른 자료는 별도로 추적한다.

## 가락 정문 횡단 표시

## 횡단 표시 생성과 회귀 검사

정문 흰 줄의 위치를 추정했지만 확인된 도형 목록에 넣은 것이 직접 원인이었다. 이전 렌더러는 흰 줄이 차도 메시 위에 있는지만 확인했다. OSM의 횡단보도 점·선도 도로망의 추정 폭으로 줄을 생성했고, 서울시 보관 도형을 도로망에 맞출 때 원본 외곽에서 자르지 않았다.

위치나 설치 현황을 확인하지 못한 표시에는 공통 검사를 적용한다. 같은 층에서 이어진 실제 차도면과 표시 양끝을 가로질러 비교한다. 두 끝이 차도 가장자리와 맞고, 횡단 방향으로 이어지는 보도나 보행섬이 있어야 표시한다. 교통섬은 차도 단면에서 뺀다. 지도 점과 선의 폭은 서울시 차도면에서 확인하고, 횡단을 나타내는 선이나 과거 보관 도형이 있으면 표시가 그 입력 범위를 벗어나지 않게 한다. 현황 목록과 대조된 기록의 도색도 원본 도형과 현재 3D 차도면의 교집합에서 생성한다. 자료가 비어 있거나 서로 맞지 않는 곳은 좌표와 보류 사유를 남겨 다음 갱신에서 확인한다.

`npm run build`는 정문 도로 한가운데에 흰 줄이 다시 그려지는지 실제 3D 메시로 검사한다. 양쪽 보도가 연결된 경우, 보행섬까지의 횡단, 반대쪽 보도가 빠진 경우, 표시가 차도 내부 또는 외부에서 끝나는 경우, 입력 외곽으로 잘려 연결이 끊기는 경우도 확인한다.

```powershell
cd frontend
node scripts/audit-road-cross-sections.cjs --crossings-only
```

이 명령은 공개 장면 전체에서 입력 종류와 도로 ID, 승인·보류 이유를 출력한다. 서울 10곳과 오포 1곳의 검사 결과 6,012건 중 949건에서 표시가 차도 안에서 끝나는 경우를 걸러냈다. 지도 범위가 겹치는 장면과 방향별 차도에서 같은 기록을 여러 번 검사할 수 있다. 확인된 시 도형은 원본 외곽 전체에 동일한 간격으로 줄을 배치하고, 중앙분리대·보행섬과 차도 이외의 부분은 표시에서 뺀다. [횡단 표시 검사 코드](../../frontend/scripts/audit-road-cross-sections.cjs)

## 노면표시 연결과 도색 투영

가락 황색 실선 `11-0000104754`의 서울시 원본은 14.29m짜리 연속 선이지만, 기존 생성기가 차도 도형 두 개가 겹치는 약 4cm에서 이를 끊었다. 원본 선의 앞뒤가 같은 지상 차도 그룹에 있고 중간까지 그 차도면이 덮는 경우 연속 구간으로 내보낸다. 점선의 시작점과 간격도 원본 거리에서 계산한다. 서울 10개 장면에서 같은 방식으로 차선의 약 1.78km를 연결했다. 생활권의 겹침이 포함된 길이다. 가락의 황색 도로 가장자리 표시 `11-0000104758`에는 시 보도면과 약 13.90m 겹치는 부분이 있어 해당 위치의 보도 경계와 도색에 추가 근거가 필요하다.

겹친 포장 삼각면을 도색 마스크로 각각 자르면 같은 위치에 도색 면을 두 번 만들 수 있다. 차도면 우선순위에 따라 같은 평면 좌표에 한 겹만 올리고, 나머지 위치는 실제 표면이 있는 곳까지만 그린다. 빌드는 겹친 포장에 16㎡ 도색을 투영했을 때 결과가 16㎡인지 검사한다. [노면표시 배치 코드](../../frontend/components/opo-surface-clip.ts) · [선형 연결 검사](../../backend/scripts/test_seoul_road_windows.py)

이번 변경 후 가락 정문 중앙선 주변 다섯 단면은 서울시 차도 경계에서 잰 폭 10.62~11.83m와 일치했다. 서울 10개 장면에서 한쪽 경계라도 오차가 0.5m를 넘는 표본이 지상 차도 532건, 고가·교량 238건 남아 있다. 원본의 실제 연석 위치와 높이가 불확실한 구간은 별도 자료로 확인한다.

## 도로 경계와 횡단 방향의 회귀 검수

차도 자료가 끝나는 곳에서 도로망 기반 포장을 잘라 이어 붙였다. 절단으로 새로 생긴 점에도 둥근 포장을 덧붙여 가까운 두 차도를 연결했다. 마포 강변 진출입로의 한 단면은 25.94m에서 69.17m로, 천호대로37길의 한 단면은 5.53m에서 49.24m로 넓어졌다. 측정 자료가 있는 장면에서는 측정 표면 바깥의 원래 도로망 정점에만 둥근 끝을 만든다. 부지 안 진입로와 주차장 포장은 차도에 이어 보일 수 있어 화면상 전체 포장 폭을 함께 집계한다.

같은 검사로 변경 전후를 비교했다. 수집 범위 끝에서 잘린 326개 단면은 폭을 계산할 수 없어 별도로 집계했다.

| 비교 대상 | 비교한 단면 | 양쪽 경계 중 0.5m 초과 이전 → 이후 |
| --- | ---: | ---: |
| 서울 10개 장면 지상 차도 | 26,953 | 414 → 163 |
| 서울 10개 장면 고가·교량 | 1,599 | 227 → 187 |

마포와 천호의 두 단면은 서울시 원본 기준 0.5m 이내로 맞았다. 가락 정문에서 차도 경계를 재현한 다섯 단면도 기존 결과를 유지했다. 이 검사는 공개 3D가 도형의 양쪽 경계를 얼마나 정확히 재현하는지 확인한다. GIS 기준일 이후 바뀐 도로, 현장 연석, 높이는 추가 대조가 필요하다.

현재 시설 목록과 연결된 횡단보도도 이전에는 OSM의 인접 중심선을 기준으로 줄의 방향을 정했다. 교차로에서 다른 진입로 방향을 따르거나 적합한 중심선을 못 찾으면 시 원본 도형이 있어도 빠졌다. 긴 축이 뚜렷하고 양쪽 방향의 단면에 충분한 차도가 이어진 시 도형은 그 축에 맞춰 줄을 한 번 배열한다. 서로 다른 횡단보도인지도 도형으로 확인한다. 차도나 교통섬 경계는 최종 3D 포장에 투영할 때 적용한다. 서울 10개 장면에서 현재 시설 목록과 연결된 원본의 표시 배치가 1,173건에서 1,279건으로 늘었다. 그중 105건은 이전에 쓰던 도로망 방향을 찾지 못했던 원본이다. 장면이 겹치면 같은 원본이 중복 집계된다.

점선은 시 원본 선형의 거리로 칠할 구간을 결정한 뒤 각 조각의 중간점을 정리한다. 이 순서가 뒤바뀌면 짧아진 길이만큼 점선 끝이 밀려 서로 다른 차도 조각 사이에서 간격이 달라진다. 화살표·설치 위치처럼 입력에 없는 상세는 해당 자료가 확보될 때 추가한다. [차선 투영](../../frontend/components/opo-streets.ts) · [횡단 방향](../../frontend/components/opo-crosswalks.ts) · [3D 단면 검사](../../frontend/scripts/audit-road-cross-sections.cjs)

## 포장 겹침과 분리대

가락 정문 접근로의 포장 마감은 같은 자동차 진입로 위에 6~10mm 높이로 얹혔다. 마감과 기존 바닥을 그대로 그리면 두 면이 겹쳐 낮은 시점에서 경계가 지글거릴 수 있다. 정문 주변 60m 사각 범위에서 본체와 마감의 3D 삼각면을 평면으로 펼쳐 합집합을 계산했다. 전체 포장 면적 약 212.76㎡를 유지하면서 중복 면적을 약 75.96㎡에서 0.001㎡ 미만으로 줄였다. 마감 도형으로 바닥을 나눠 재질을 입히고, 차선과 횡단보도는 같은 포장 높이에 붙인다. 빌드에서 진입로 두 좌표를 위에서 아래로 검사해 바닥이 빠지거나 두 높이에서 겹치면 실패한다. [진입로 마감](../../frontend/components/opo-site-surfaces.ts) · [회귀 검사](../../frontend/scripts/audit-road-cross-sections.cjs)

도로망 기반 포장도 같은 층의 띠끼리 겹치던 곳에서 한 겹만 남긴다. 조사 도형을 경계로 잘린 포장의 끝이 원래 도로 가운데 굽은 점과 같을 수 있다. 끝점처럼 보이더라도 실제 도로 끝이나 분기가 아니면 원형 포장을 그리지 않는다. 마포 진출입로 한 단면은 9.38m짜리 시 차도가 분리 공간을 넘어 31.60m로 이어졌고, 청계천 주변 진출입로 단면은 21.38m에서 46.11m까지 이어졌다. 수정 후 두 단면 모두 시 자료와 양쪽 경계가 0.5m 이내다.

서울 10개 장면의 같은 표본에서 좌우 경계 오차가 0.5m를 넘는 지상 단면은 163건에서 150건, 고가·교량은 187건에서 64건으로 줄었다. 가락 정문 중앙선과 확인된 횡단보도 도색은 기존 배치와 면적을 유지했다. 항공영상에 시 경계를 겹쳐 확인한 마포 강변부는 진출입로와 아래 차도가 교차했고, 천호·가락의 검토 단면은 구조물과 그림자에 일부 가려졌다. 이곳의 폭은 시 도형과 렌더러 사이의 일치 여부까지 확인했다. 현장 연석 폭으로 확정하려면 층별 도형 또는 경계가 보이는 영상을 추가 대조해야 한다. [항공영상 지도와 해상도](https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer)

## 측정 경계에 닿는 추정 포장

기존 추정 포장은 정해진 폭으로 띠를 만든 뒤 확인된 차도 면과 겹치는 부분만 잘랐다. 띠가 조사된 경계를 넘어간 경우 경계 반대편의 조각이 남아 차도 폭을 넓히거나 옆 도로를 이어 붙일 수 있었다. 성동구 사근동11길 표본에서는 약 1.55m의 빈 경계를 추정 포장이 연결했다. T-GIS 차도 면과 서울시 수치지형도의 포장 도형에서 같은 간격을 확인했다. [서울시 교통안전시설물관리시스템](https://tgis.eseoul.go.kr/map/mapMain.do) · [서울시 수치지형도](https://news.seoul.go.kr/gov/archives/528208)

추정 띠를 만드는 각 단면에서 도로 중심선을 기준으로 좌우를 검사한다. 지상은 확인된 차도·보도, 고가는 조사된 고가 차도에 닿는 첫 경계까지 폭을 제한한다. 중심선이 측정된 면에 들어가면 그 단면에 맞추고 겹치는 추정 포장을 제거한다. 서울 10개 장면의 같은 표본에서 양쪽 경계 중 0.5m 초과 오차는 지상 140건에서 120건, 고가 64건에서 56건으로 줄었다. 이전에 오차 범위 안에 있던 표본 중 새로 기준을 벗어난 곳은 없었다. 횡단보도 검사 6,191건은 같은 결과를 유지했다.

### 통행 제한 포장과 도로망 이음부

정릉로 옆 동소문로40길은 원본 도로망에서 `motor_vehicle=no`로 기록되어 있었지만 미조사 포장에 일반 차도와 같은 아스팔트를 적용했다. 낮은 곳의 넓은 차도와 포장이 붙어 보이며 실제 차도의 끝을 가렸다. 시 자료가 우선인 장면에서는 차량 통행이 제한된 길의 미조사 포장을 보행 계열 마감으로 표현한다. 원본이 아스팔트로 명시한 포장은 재질을 유지하고, 공개 차량 통행 차도와 이어져 보이는 포장 범위를 별도로 잰다. [동소문로40길 OSM 원본](https://www.openstreetmap.org/way/415374926)

차량 통행 도로가 지도 속성이나 고가 진입 지점에서 두 웨이로 나뉠 때도 원형 포장이 양쪽 끝에 추가됐다. 도로망에서 두 접근 방향만 만나는 완만한 연결점은 공통 단면에 양쪽 띠를 맞춘다. 조사된 포장이 있는 경우 두 띠를 같은 층의 조사 경계에서 자른다. [차도 렌더러](../../frontend/components/opo-streets.ts)

서울 공개 장면 10곳에서 중복을 뺀 단면을 비교한 결과 좌우 오차가 0.5m 초과인 곳은 69개에서 44개로 줄었다. 통행 제한 포장 처리로 21곳, 이어지는 두 웨이의 공통 단면으로 4곳이 기준 안에 들어왔다. 새로 기준을 벗어난 단면은 없었고 횡단보도 검사 6,774건의 판정도 이전과 같았다. 이 수치는 시 자료와 렌더링 경계의 비교 결과다. 도로 경계를 항공영상으로 추가 대조할 때는 교차로에 비스듬히 들어온 옆 도로나 나무·구조물로 가려진 연석을 따로 확인한다. ### 이동할 때 보이는 그림자 가장자리

시점이 이동해 태양광 그림자 영역을 다시 잡을 때 이전 코드는 그림자 맵을 픽셀보다 작은 단위로 이동시켰다. 고정된 표면의 그림자 가장자리에서도 픽셀 샘플 위치가 달라질 수 있었다. 광원 좌표계에서 그림자 맵의 픽셀 단위로 영역을 이동하고, 현재 장면의 1,024와 2,048 해상도에서 고정된 지점의 그림자 좌표가 정수 픽셀만큼 움직이는지 검사한다. ### 이동할 때 보이는 원거리 도색

기존 도색 렌더러는 거리와 실제 도색 폭으로 화면 크기를 추정했다. 지면을 비스듬히 보면 같은 폭의 줄도 화면에서 훨씬 얇아진다. 이때 카메라가 조금 움직여도 한 픽셀에 찍히는 표본이 바뀌어서 줄 가장자리가 들쭉날쭉해졌다. 화면상 크기에 따라 도색을 흐리게만 하는 방식은 가락 횡단보도의 검수 시점에서 밝기가 줄고 변동이 커졌다.

도로 표면에 자른 뒤에도 도색의 폭과 길이 좌표를 유지한다. 카메라 기준 깊이가 35m를 넘고 화면에서 짧은 쪽 치수가 1.5픽셀 미만인 도색은 픽셀에 실제로 겹치는 면적만큼 채색한다. 이를 위해 픽셀 단위의 좁은 범위를 렌더러에서 샘플링한다. 원본 선형과 폭, 차도에 잘린 도형은 같은 좌표를 쓴다. 가까운 도색은 기존 멀티샘플링으로 표시한다. [도색 필터](../../frontend/components/opo-paint-filter.ts) · [픽셀 영역을 쓰는 선 필터](https://developer.nvidia.com/gpugems/gpugems2/part-iii-high-quality-rendering/chapter-22-fast-prefiltered-lines)

가락과 잠실의 시 조사 횡단보도 메시를 사용해 Chromium WebGL2의 970×1302 버퍼에서 비교했다. 같은 카메라 움직임의 고해상도 기준 영상과 대조했을 때 40m 시점의 움직임 오차는 약 50%, 56% 줄었다. 12m와 25m에서는 이전 검수 결과와 일치했다. 공개 서울 장면 10곳의 도색 좌표와 차도폭 검사, 전체 횡단보도 6,774건의 판정도 같았다. 별도로 588×789 브라우저 화면에서 가락 걷기와 잠실 운전을 확인했다. 이 검수는 실제 iPhone의 렌더링 성능까지 포함하지 않는다. [도로 렌더링 검사](../../frontend/scripts/audit-road-cross-sections.cjs)

정점마다 반복되던 필터 방향값은 삼각형별 텍스처에 모으고, 도색의 상대 좌표는 16비트로 보관한다. 가장 큰 장면에서 필터 데이터의 추가 용량은 약 62.5MiB에서 18.3MiB로 줄었다. 최적화 후 도색의 위치 버퍼와 차도폭·횡단보도 판정을 다시 대조했다.

좁고 가파른 삼각면을 지나는 도색은 GPU에 보낼 좌표로 먼저 반올림한 뒤, 그 좌표에서 도색 높이와 폭·길이 좌표를 함께 계산한다. 마포대교 노면에서 발견된 약 6~8mm 높이 오차를 고가 메시 검사로 재현했다. 좁은 삼각면에 도색을 붙이는 배치 검사도 추가했다. [표면 투영](../../frontend/components/opo-surface-clip.ts) · [도로 렌더링 검사](../../frontend/scripts/audit-road-cross-sections.cjs)

## 진출입로 차로 수와 폭

도로망에 폭과 차로 수가 빠지면 기존 코드는 간선도로 진출입로에도 본선의 기본 폭 13m를 적용했다. 강변북로의 OSM `474754678`과 국가교통정보센터 표준 링크 `1130030100`은 표본 전체에서 같은 진출입로를 가리키며, 국가 자료의 차로 수는 1이다. 이 진출입로의 추정 포장 띠가 옆 분리 공간을 채워 본선 차도 두 곳이 함께 보였다.

현재 서울 공개 장면의 일방통행 진출입로 가운데 폭과 차로 수가 비어 있는 길을 표준노드링크와 대조했다. 최대 6m 간격으로 진행 방향, 층위와 5m 이내 거리를 비교한다. 표본의 80% 이상에서 순서대로 연결된 진출입로들이 같은 차로 수를 보고할 때만 사용한다. 가까운 본선, 다른 층의 링크 또는 다른 차로 수 후보가 더 잘 맞는 위치는 근거에서 뺀다. 배포에는 19개가 연결됐다. 14개는 1차로, 5개는 2차로다. 원본 도로망의 양 끝과 중간 노드 및 좌표까지 같을 때 이 차로 수를 적용한다. [국가교통정보센터 표준노드링크](https://www.its.go.kr/nodelink/nodelinkRef) · [국토교통부 도로 유형·차로 속성 정의](https://www.codil.or.kr/filebank/moct2014/202301/MOCT3000_0.PDF?nserialno=3000)

시 차도 경계를 확보한 곳은 그대로 사용한다. 표준 링크에서 얻은 차로 수는 도형이 비는 구간의 포장 폭 계산에 쓰고 도색은 기존 도색 원본을 사용한다. 강변북로 한 단면은 렌더러에서 41.01m까지 이어졌으며, 수정 후 시 차도 경계와 화면 모두 24.49m였다. 서울 10개 장면의 기존 지상 표본에서 경계 오차가 0.5m를 넘는 곳이 150건에서 140건으로 줄었다. 잠실 주변 합류로처럼 국가 링크가 다른 분기만 따라가거나 연석이 항공영상에서 가려진 곳은 추가 대조가 필요하다. ### 측정 차도에서 벗어난 진출입로 중심선

마포 강변북로 진출입로의 지도 중심선 한 점은 최신 서울시 차도 경계에서 벗어났다. 같은 진출입로로 대조된 국가 표준노드링크는 측정 차도 안에 있다. 기존 배치는 지도 중심선이 도형 밖에 있으면 자료가 없는 도로로 해석해 분리 공간에 추정 포장을 만들었다. 항공영상에는 차도 옆의 녹지 경계가 보인다. [표준노드링크 자료실](https://www.its.go.kr/nodelink/nodelinkRef) · [항공영상 출처](https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer)

장면별 생성 단계에서 등록된 지상 진출입로의 원본 정점과 진행 방향을 대조한다. 같은 표준 링크로 5m 이내에서 옮길 수 있고 옮긴 점이 측정 차도 안에 있는 내부 정점만 조정한다. 도로의 끝점과 다른 도로가 함께 쓰는 정점을 보존한다. 조정으로 기존 차도 연결이 끊기거나 측정 범위가 줄어드는 경우는 제외한다. 생성한 중심선은 추정 포장을 판단하는 구간과 3D 이동 경로에 함께 사용한다. 차도 도형, 보도 도형과 원본 도색은 기존 좌표를 유지한다.

강변북로 표본 한 곳은 추정 포장이 옆 차도와 이어지면서 화면 폭이 30.88m까지 늘어났다. 중심선 조정 후 렌더링 폭은 서울시 차도 도형과 같은 19.46m다. 같은 진출입로가 포함된 마포 장면 두 곳에 적용했고, 양쪽 경계 중 0.5m를 넘는 지상 오차 표본은 합계 11건 줄었다.

도로 창을 다시 생성하기 전에 같은 국가 표준노드링크로 진출입로 근거를 갱신한다. 배치는 같은 링크 아카이브와 서울시 도로 스냅샷을 사용했는지 확인한다. [진출입로 중심선 생성](../../backend/scripts/prepare_seoul_road_windows.py)

### 진출입로 굴곡과 추정 포장

## 최신 횡단보도 도형과 중앙 구간

### 기존 도형과 겹치는 최신 횡단보도

전체 서울 장면을 검사하니 기존 도형이 조금만 겹쳐도 최신 도형을 중복으로 분류했다. 시설 목록과 연결되지 않아 실제로 화면에 그리지 못한 기존 도형도 같은 우선순위를 갖고 있었다. 이제 시설 목록과 연결된 최신 도형이 확인되지 않은 기존 도형과 겹칠 때, 교집합이 양쪽 면적의 절반 이상인 경우 해당 외곽을 `supersedes`에 기록한다. 최신 도형을 차도에 올릴 수 있을 때에만 해당 기존 도형을 그리기에서 제외한다. 기존 도형이 이미 시설과 연결됐거나 어느 외곽을 교체할지 불분명하면 기존 검증을 유지한다.

서울 공개 장면 10개의 3D 메시에서 흰 줄이 없거나 0.5㎡ 이하였던 위치 393건에 도색이 생겼다. 중복 생활권을 합치면 261개 시설이다. 기존에 최신 자료로 보강한 179건도 계속 그려졌다. 첫 검사에서는 새 도형 중 7개 시설의 횡단 방향이 확인되지 않았다. 잠실 `06-0000009350`은 0㎡에서 30.20㎡로 늘었으며 운영 빌드의 회귀 검사에 포함했다.

### 횡단보도의 방향과 보행섬

길이와 폭이 비슷하거나 불규칙한 횡단 도형은 도형 비율만으로 횡단 방향을 고르기 어렵다. 시설 목록과 연결된 도형은 원본 각 변에서 두 방향을 만들고, 가운데와 양쪽에서 차도 단면과 보행 연결을 검사한다. 단면 3개 중 2개 이상에서 도색 양쪽이 같은 차도의 끝과 맞고 양쪽 보행 연결이 이어져야 한다. 두 차도 경계가 각각 0.30m 이내에 맞는 경우 한쪽에서 자료로 확인되는 보행 연결도 방향 근거로 사용한다. 검사를 통과한 방향들이 가장 근거가 많은 후보에서 20도 이내로 모여야 최종 방향을 결정한다.

서울시 T-GIS `C080_A`의 보행섬 중 확인된 횡단보도와 가깝고, 지상 차도 외곽에 포함되며, 기존 보도·교통섬이나 고가와 겹치지 않는 도형 16개를 연결했다. 길음 보행섬 `3001`은 서울시 수치지형도의 교통섬 외곽과 대조했다. 공통 렌더러는 해당 외곽을 차도·도색·폭 계산에서 빼고 보행 연결에 포함한다. 섬의 턱은 공통 보도 높이를 사용한다. [서울시 T-GIS 시민용 지도](https://tgis.eseoul.go.kr/map/mapMain.do) · [서울시 수치지형도 교통섬](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1A_A0053326.zip)

서울 공개 장면 10개에서 해당 최신 도형 762건을 3D 메시와 대조했다. 방향 확인이 남았던 7개 시설은 모두 원본 도형 안에 도색이 생겼다. 이 중 잠실 보행섬으로 이어지는 횡단보도 `06-0000030331`을 운영 빌드의 검증에 포함한다. 이전 빌드에서 그려졌던 최신 도형도 모두 확인했다.

## 고가 차선의 층위 연결

이전 차선 수집은 서울시 T-GIS `A058_L`의 지상 코드 `EVE_CDE=001`만 읽었다. 같은 스냅샷의 정상 사용·지도 표출 고가 차선 `EVE_CDE=002` 979건은 이 단계에서 빠졌다. 고가 차도 폴리곤이 있는 곳에서도 포장 위에 표시할 원본이 남지 않았다. [서울시 차선 도형](https://data.seoul.go.kr/dataList/OA-15537/S/1/datasetView.do) · [서울시 교통시설물 공통 코드 정의서](https://data.seoul.go.kr/dataList/OA-15541/F/1/datasetView.do)

`prepare_seoul_elevated_markings.py`는 EPSG:5186에서 이 고가 선을 기존 S-Map 고가·도로교 경계와 겹쳐, 한 시설에만 속하는 구간을 내보낸다. 같은 도시 스냅샷과 같은 구조물 아카이브가 함께 있을 때만 표시한다. 원본 차선 도형 ID, 시설 ID, 차선 종류, 점선 시작 거리를 보존한다. 렌더러는 시설 ID로 실제 높이가 적용된 고가 차도 메시를 찾아 도색을 붙인다. 지상 횡단보도의 도색 범위와 추정 차도는 이 고가 차선에 영향을 주지 않는다. [서울시 도로교 도형](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1A_A0070000.zip) · [서울시 입체교차부 도형](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1A_A0090000.zip)

공개 서울 장면 10개에 적용해 6개 장면, 7개 고가 시설에서 원본 차선 30건을 연결했다. `node frontend/scripts/audit-road-cross-sections.cjs --verify-elevated`로 전체 장면의 고가 도색 삼각형이 실제 렌더링 차도 높이에서 1.8cm 위에 놓이는지 검사한다. 고가 외곽이 서로 겹치거나 대응하는 고가 경계가 없는 구간에는 추가 자료가 필요하다. 이 검사는 고가 차도의 현장 높이와 실제 폭을 별도로 측정한 결과와 구분한다.

## 고가 차도의 교통섬과 분리 경계

S-Map 입체교차부 외곽은 교통섬을 포함한 구조물의 외곽이다. 이전 렌더러는 이 전체를 아스팔트로 처리했다. 차도 양쪽이 분리된 내부순환로에서 폭 검사가 섬을 지나 반대쪽 포장까지 합산할 수 있었고, 도색 투영에 사용한 포장 면도 교통섬을 포함했다. [서울시 S-Map 입체교차부](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1A_A0090000.zip)

서울시 T-GIS `C080_A`는 교통섬과 중앙분리대의 평면 경계를 제공한다. 별도 층위 필드가 없어 EPSG:5186에서 생활권 내 도형 면적의 99% 이상이 고가 외곽 하나에 있으며 지상 차도·보도와 유의하게 겹치지 않는 경우에 연결한다. 여러 층이나 지상과 겹치는 위치는 근거를 더 확인할 대상으로 남긴다. [서울시 T-GIS 시민용 지도](https://tgis.eseoul.go.kr/map/mapMain.do)

연결된 경계와 원본 관리번호를 `pavement.json`의 시설별 `dividers`에 저장한다. 고가 차도와 고가 도색이 같은 경계를 사용하고, 추정 포장이 섬을 다시 덮지 않도록 구조물 전체 외곽은 추정 포장 제외 범위에 남긴다. 경계의 높이는 장면의 고가 표면에서 가져오며, 교통섬 턱 14cm는 공통 표시 높이로 적용한다. 폭 검사는 두 차도를 가르는 경계를 같은 층에서 사용한다.

```powershell
python backend/scripts/collect_seoul_tgis_wfs.py .road-source-cache tgis-dividers.sqlite --layer C080_A
python backend/scripts/prepare_seoul_elevated_dividers.py tgis-dividers.sqlite --output review-dividers

```

2026-11-22 스냅샷에서 서울 공개 장면 10개를 검사했다. 왕십리삼성과 청계천현대에 함께 들어오는 내부순환로 시설 한 곳에서 교통섬 2개를 연결했다. 도로망 중심이 분리 경계 안에 있는 단면 13곳에서 양쪽 차도 폭을 각각 비교했다. 한 단면에서 차도 폭 각각 약 13.78m와 12.15m, 사이의 교통섬 약 0.58m가 원본과 일치했다. 빌드에서 고가 도색이 포장에 붙는지와 교통섬이 원본 도형만큼 보이며 아스팔트와 거의 겹치지 않는지 검사한다.

### 고가 본선 중심선과 추정 포장

청계천 내부순환로의 OSM 중심선이 조사 외곽을 벗어나면서 추정 포장이 같은 층의 차도 바깥에 생겼다. 최대 오차가 나온 단면에서 양방향 국가 표준노드링크는 서울시 구조물 안에 있었고, OSM 웨이 `1059249202`만 바깥으로 치우쳐 있었다. 차도 한쪽의 조사 폭은 9.676m였고 이전 3D 장면에서는 추정 포장까지 이어져 19.261m로 보였다. [국가 표준노드링크](https://www.its.go.kr/nodelink/nodelinkRef) · [서울시 수치지형도](https://news.seoul.go.kr/gov/archives/528208)

`prepare_seoul_elevated_alignment.py`는 같은 도로명과 진행 방향, 표준 링크의 연결, 같은 고가 차도 안에 있는지를 함께 확인한다. 이 근거를 충족하는 중심선 좌표를 바로잡고 그 좌표를 기준으로 조사 포장 범위를 다시 계산한다. 같은 도로망과 GIS 원본을 쓰는 장면은 중심선도 공유한다. 실제 분기점의 좌표를 보존하고, 같은 방향의 두 웨이만 만나는 접점은 양쪽이 같은 표준 링크와 차도 면에서 확인될 때 한 좌표로 함께 갱신한다.

왕십리삼성과 청계천현대에 같은 기준을 적용했다. 위 단면의 3D 폭은 9.676m가 되었으며 배포 빌드에서 확인한다. 서울 공개 장면 10개의 도로 경계 오차 0.5m 초과 표본은 겹치는 장면을 제외하고 94곳에서 69곳으로 줄었다.

긴 고가 웨이의 일부만 잘못된 쪽 차도에 있으면 표준 링크를 구간별로 대조한다. 같은 도로명과 방향, 링크 연결을 확인하고, 링크 길이의 98% 이상이 분리대를 뺀 조사 차도에 있으며 지상 차도와 겹치는 길이는 1% 이하여야 근거로 쓴다. 변경 구간 양쪽의 연결점과 일반 분기점을 유지한다. 각 변경이 분리대 침범을 15m 이상 줄이고 차도 밖으로 새로 나가지 않는지 확인한다. 이동과 차선 배치에 같은 교정 진행축을 쓴다. [고가 진행축 추출기](../../backend/scripts/prepare_seoul_elevated_alignment.py)

공개 장면 10곳을 다시 검사해 두 장면이 함께 쓰는 내부순환로의 한 웨이에 적용했다. 진행축이 조사된 분리대에 겹친 길이는 213.32m에서 약 1.34m로 줄었다. 같은 교정 진행축에 연결된 원본 중앙선 약 409m를 고가 차도에 복원했다. 여러 장면에 겹쳐 나온 선형을 한 번만 센 길이다. [서울 전역의 중앙선 검사](seoul-road-bulk-sources.md#서울-전역의-중앙선-검사)

이 교정으로 각 장면에서 고가 차도 단면 13곳을 추가로 비교할 수 있었고, 모두 서울시 조사 차도 양쪽 경계와 0.5m 이내에서 일치했다. 전체 공개 장면의 횡단보도 검사 결과와 기존 차도폭 오차 표본은 이전 빌드와 같았다. 남은 원본 중앙선 중 분리대 내부 약 34.8m와 다른 고가 외곽이 겹치는 약 7.4m는 보류했다.

## 앞으로 사용할 데이터 구조

1. **서울 전역을 한 번 수집하고 생활권으로 자른다.** 서울시 T-GIS 차선·정지선·차도·보도·횡단보도를 같은 좌표계와 조회 범위로 읽는다. 감속 표시와 도로 중심선은 별도 출처를 연결한다. 차선과 차도를 같은 생활권 경계와 여유 범위로 내보내고, 서로 겹치는 장면에서 같은 구간 데이터를 공유한다. 원본의 관측·설치일과 자료 조회 시각, 좌표계와 피처 식별자를 함께 기록한다. [서울시 T-GIS 시민용 지도](https://tgis.eseoul.go.kr/map/mapMain.do) · [일괄 수집 방법](seoul-road-bulk-sources.md#자동으로-갱신하고-검사하는-명령)
2. **도로 구간에 형태와 표시를 연결한다.** 미터 단위 좌표계 EPSG:5186에서 차도 외곽, 방향별 차도, 교차로, 중앙분리대, 보도 경계, 고가·지하의 층위를 정한다. 차선·정지선을 연결할 때 도로와 겹치는 길이, 진행 방향과 각도, 좌우 위치를 함께 확인하고 연결된 도로·원본 도형·검증 상태를 저장한다. 바로 옆 차도나 고가 위 차도를 구분할 수 없으면 해당 구간은 확인 필요로 남긴다.
3. **경계와 높이를 공유한다.** 같은 층의 차도·교차로·진입로는 공유 경계에서 맞물리도록 만들고 중앙분리대와 보도는 그 경계에서 분리한다. 차량 이동 경로와 차선 도색은 같은 차도 면을 사용한다. 차도 면을 확보하지 못한 곳에서는 도로망으로 맥락과 이동만 표현하고 확인된 차선 범위를 별도로 저장한다.
4. **노면표시의 관계를 먼저 결정한다.** 정지선, 횡단보도, 감속 표시를 각각의 원본 유형과 도형으로 처리한다. 실제로 겹치는 범위와 원본에 기록된 통행 관계로 끊김을 결정한다. 손실이 생긴 차선은 잘린 짧은 조각을 배치하는 대신 원본과 도로 연결부터 검토한다. 새 원본으로 해결하기 어려운 곳만 날짜와 위치를 기록해 항공영상이나 로드뷰로 대조한다.

## 배포 전 점검 기준

- **자동 검사를 먼저 실행한다.** 모든 장면에서 자료 사용 가능 범위, 차도 연결 결과와 근거, 횡단 도형에 의한 삭제 길이, 차도 면 밖 길이, 남아 있는 도색 길이를 별도로 집계한다. 생활권 단위로 갱신 전후를 비교하고 누락된 레코드는 원본 ID와 좌표로 추적한다.
- **근거 있는 중단 지점을 제외하고 누락을 표시한다.** 차선이 보도·섬·다른 층위에 들어가거나, 정지선이 적용 대상 차도 끝에 붙지 않거나, 같은 높이의 차도·보도가 의도 없이 겹치면 그 구간을 공개 검수에서 보류한다. 연속 실선이 설명 없이 3m 이상 비는 경우와 갑자기 전부 사라지는 경우는 우선 검수 항목으로 삼는다. 3m는 이번 조사에서 사용한 초기 검수 기준이며 자료의 측량 정확도를 뜻하지 않는다.
- **고친 장소를 자동 검사의 기준점으로 사용한다.** 가락 정문처럼 감속 표시와 흰 줄, 정지선이 인접한 곳, 잠실 르엘의 넓은 차도, 성북·성동·마포의 공유 경계, 오포의 차선 미수집 상태를 검수 사례로 둔다. 자동 검사에서 좌표를 찾고, 대표 사례는 모바일 눈높이와 조감에서 비교한다.
- **적용 순서를 지킨다.** 먼저 공통 수집 범위와 원본 식별자 기록을 맞춘다. 다음으로 도로별 차선 연결과 포장 경계를 검사하는 배치를 만든다. 마지막으로 검사를 통과한 도로 구간을 모든 장면에 다시 생성하고 이 표와 같은 지표를 비교한다.
