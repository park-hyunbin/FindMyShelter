# 서울 전역의 차선·차도 일괄 수집

2026-11-22에 서울시 교통시설물관리시스템(T-GIS) 시민용 지도에서 서울 25개 구를 포함하는 범위의 차선·차도·보도·횡단보도를 한 번에 받았다. 새 기본 자료는 같은 지도에서 뽑은 이 네 레이어다. 도시 단위 공간 인덱스에서 단지나 생활권에 필요한 부분을 꺼내 쓰고, 표준노드링크로 빠진 구간을 검사한다.

## 서울시 시민용 지도 일괄 수집 결과

시민용 지도가 읽는 공간정보 조회(WFS)에 EPSG:5186의 6.5km 타일을 보내고 경계에 중복된 응답을 합쳤다. 42개 요청 타일을 네 레이어에 공통으로 사용했다. 갱신할 때 새 날짜의 캐시로 한 번 실행한다. 수집 전후 서버 레코드 수와 SQLite에 합친 수가 같아야 다음 단계로 진행한다. 조회 때마다 바뀌는 응답 ID 대신 좌표와 속성이 같은 레코드를 기준으로 중복 응답을 제거한다. 수집 기간과 해시는 측량일·설치일과 별도로 기록한다. [서울시 T-GIS 시민용 지도](https://tgis.eseoul.go.kr/map/mapMain.do)

| 서울시 레이어 | 응답 레코드 | 검수에 쓰는 상태 |
| --- | ---: | --- |
| 차선·정지선 `A058_L` | 665,498 | 정상 작업·사용·표출 조건을 통과한 368,312건. 25개 구 코드가 모두 있다. |
| 차도 외곽 `A001_A` | 313,728 | 표출 282,759건 중 면을 만들 수 있는 도형을 사용한다. |
| 보도 `A003_A` | 52,672 | 표출 49,287건 중 면을 만들 수 있는 도형을 사용한다. |
| 횡단보도 `A004_A` | 124,410 | 정상 작업·사용·표출 조건을 통과한 41,091건. 이번에는 수집 범위까지 검증했다. |

응답에는 숨김과 이력도 들어 있다. 차선 인덱스는 표시 유형을 해석할 수 있고 25cm가 넘는 선형을 사용한다. 조회일보다 설치일이 나중인 차선은 이미 칠해진 표시로 간주하지 않고 원본에 남긴다. 이번 자료에서 해당 조건에 걸린 차선은 5건이다. 조회 전후 개수 검사는 누락·중복을 찾는 용도이며, 제공 서버의 응답이 단일 시점에 고정되어 있음을 보장하려면 제공처의 버전 식별자가 필요하다.

### 도로면을 바꿨을 때 확인한 원인

- **가락 정문 중앙선 `11-0000104759`**은 기존 차도면과 겹치는 길이가 0m였다. 같은 중앙선 30.81m가 새 공식 차도면 하나와 전부 겹쳤고 보도와는 겹치지 않았다. 이 위치에서는 차선 좌표를 그대로 두고 차도 원본을 바꾸면 잘림 원인을 제거할 수 있다.
- **서울 전체에서 관리번호·도색 유형·좌표가 같은 선 60,441개**를 골라 도로면만 비교했다. 전체 2,472.2km 중 단일 차도면에 겹치는 길이가 2,281.2km에서 2,422.8km로 늘었다. 다른 단지에도 공통으로 발생한 차도면 불일치 사례다.
- **전체 원본**에서 단일 차도면과 겹친 차선 길이의 비율은 86.6%에서 95.6%로 올랐다. 두 자료의 차선 구성이 다르므로 위의 동일 선형 비교를 함께 본다. 평면 겹침은 설치 시점이나 고가·지하차도의 층위 확인을 대신하지 않는다.

### 서울 25개 구 도로 링크 재점검

같은 표준노드링크 62,575개와 같은 검사 규칙을 사용해 구간별 후보를 비교했다. 길이는 양방향 도로 링크를 각각 센 값이다.

| 도로 링크 기준 | 기존 자료 | T-GIS 시민용 지도 |
| --- | ---: | ---: |
| 같은 차도면에서 차선 후보 발견 | 3,110.9km | 3,247.1km |
| 차도면을 찾았으나 차선 후보 없음 | 626.2km | 560.8km |
| 차도면을 하나로 정할 수 없음 | 2,151.6km | 2,080.7km |

차선 후보가 한 번도 나오지 않은 링크는 20,693개에서 18,634개로 줄었다. 이 중 2,315개는 2차로 이상이고 표준링크가 2024년 1월 1일 이후 갱신됐다. 이 그룹부터 정밀도로지도와 대조하고, 정밀도로지도에 빠진 골목·단지 내부는 별도 부지 도로 자료에서 확인한다. 차선이 있는지 모르는 도로와 공식 자료에서 차선이 없다고 확인한 도로를 구분한다. [국가교통정보센터 표준노드링크](https://www.its.go.kr/nodelink/nodelinkRef)

같은 새 인덱스로 입체도로도 다시 대조했다. 일반도로와 입체도로 링크가 모두 16m 안에 잡힌 차선 길이는 922.6km였다. 이 길이는 구조물이 가까워 별도 검증이 필요한 범위다. 정밀도로지도나 구조물 도형에서 해당 차도의 높이와 연결이 확인되면 차선을 올리고, 평면 좌표만 겹치는 경우에는 층위를 미확정으로 둔다. [도로중심선·입체도로 대조 코드](../../backend/scripts/reconcile_seoul_marking_links.py)

### 서울 전역의 중앙선 검사

같은 2026-11-22 스냅샷에서 지상으로 기록된 활성 중앙선의 관리번호는 29,570개이고, 색칠 전 원본의 선형 길이는 약 1,697.48km다. 25개 구가 포함되며 구 코드가 비어 있는 기록도 따로 집계한다. 한 차도면과 겹친 길이는 1,654.12km, 차도면을 여러 개 찾은 길이는 27.07km, 차도·보도 모두 밖에 있던 길이는 13.23km다. 차도와 보도가 겹치거나 보도만 있는 나머지 구간은 같은 층의 차도를 확정할 근거가 필요하다. 갱신 시 장면 검사 JSON의 `ground_centerlines`에서 구별 차도 일치 상태와 길이를 확인한다. 한 원본이 여러 상태를 지날 수 있으므로 상태별 건수에 같은 원본이 포함될 수 있다. [서울시 차선 원본](https://data.seoul.go.kr/dataList/OA-15537/S/1/datasetView.do) · [구별 집계 코드](../../backend/scripts/audit_seoul_scene_markings.py)

공개 장면 10곳의 범위를 합쳐 대조했을 때 지상으로 기록된 원본 중앙선은 72.81km였고 이전 배포의 지상 출력은 67.05km였다. 빠진 5.77km 중 4.80km는 단일 차도면에 있으면서 입체도로가 가까운 기록에 속했다. 입체도로 주변에서 한 표본이 통과하지 못하면 같은 원본 구간의 확인된 부분까지 전부 빠지는 것이 공통 원인이었다. 고가 외곽에 대부분 겹치는 지상 기록도 있어 차도와 진행 방향을 양쪽 층에서 다시 확인해야 했다. [층위 확인과 배치 규칙](road-markings.md#입체도로-주변의-지상-차선)

이후 서울 전역에서 단일 차도면에 있고 입체도로가 가까운 중앙선 187.94km를 대상으로 양방향 표준 링크를 다시 대조했다. 25개 구에서 190개 관리번호의 7.67km가 같은 도로의 반대 방향 링크 쌍으로 추가 확인됐다. 도시 전체 수치는 조사 차도·보도 도형으로 검사한 선형 길이다. 공개 장면 10곳의 실제 포장과 다시 대조한 결과 두 장면에서 191.84m가 추가됐다. 장면에 겹쳐 나온 선형을 한 번만 세고, 원본 관리번호별로 15cm 이내에 이미 있던 도색은 제외했다. 기존 도색의 위치나 길이가 줄어든 곳은 없었다. [층위 확인과 양방향 링크 판정](road-markings.md#입체도로-주변의-지상-차선)

### 자동으로 갱신하고 검사하는 명령

SQLite와 타일 캐시는 원본 자료 보관 경로에 둔다. 새 차선 자료를 받을 때 같은 범위의 차도와 보도를 함께 갱신한다. 다음 명령으로 단지별 다운로드 없이 다시 검사할 수 있다.

```powershell
uv run --with pyproj python backend/scripts/collect_seoul_tgis_wfs.py ../road-source-cache/tgis-2026-11-22 ../road-source-cache/tgis-live.sqlite
uv run --with pyshp --with shapely --with pyproj --with openpyxl python backend/scripts/index_seoul_road_markings.py ../road-source-cache/tgis-live.sqlite ../road-source-cache/tgis-live-index.sqlite
uv run --with pyshp --with shapely --with pyproj --with openpyxl python backend/scripts/audit_seoul_link_coverage.py ../road-source-cache/tgis-live-index.sqlite ../road-source-cache/national-road-links-2026-11-11.zip ../road-source-cache/tgis-link-coverage.sqlite
uv run --with pyshp --with shapely --with pyproj --with openpyxl python backend/scripts/audit_seoul_scene_markings.py ../road-source-cache/seoul-marking-index.sqlite ../road-source-cache/tgis-live-index.sqlite
```

장면 검사 JSON의 `identical_markings`에는 두 원본에서 관리번호가 각각 하나이며 종류와 좌표가 모두 같은 차선만 모은 대조 결과가 들어간다. 자료의 구성 변화와 차도면 변경의 영향을 따로 확인할 수 있다.

시민용 지도 스냅샷은 수집·검수에 사용했다. 공개 장면용으로 가공할 때는 제공처의 이용 조건과 출처표기 범위를 확인한다. 서울 열린데이터광장의 차선·횡단보도 공개 파일은 공공누리 1유형이고, 이 파일의 이용 조건과 시민용 지도 조회의 이용 조건은 출처별로 기록한다. [서울시 차선 공개 파일](https://data.seoul.go.kr/dataList/OA-15537/S/1/datasetView.do) · [서울시 횡단보도 공개 파일](https://data.seoul.go.kr/dataList/OA-15554/S/1/datasetView.do)

[서울시 차선 자료](https://data.seoul.go.kr/dataList/OA-15537/S/1/datasetView.do) · [에스맵 오픈랩](https://openlab.eseoul.go.kr/) · [2026년 버스전용차로 자료](https://data.seoul.go.kr/dataList/OA-22396/F/1/datasetView.do)

관리번호가 일치한 버스전용차로 중 두 시점의 선형 거리를 계산할 수 있었던 3,032개를 대조했다. 615개는 두 선형의 최대 이격 거리(Hausdorff 거리)가 1m를 넘었고, 그중 414개는 5m를 넘었다. 선형이 이동한 경우와 길이·분할 범위가 달라진 경우가 함께 들어 있는 값이다. 오래된 원본의 차선을 옮겨 맞추기 전에 최신 도형을 확인해야 하는 이유다.

2023년 시설물 현황의 대표 좌표 356,711개를 2021년 기본 차선과 2026년 버스전용차로를 병합한 선형에 대조했다. 가장 가까운 선에서 1cm 이내인 좌표는 302,768개였고, 5m 안에 선이 하나도 없는 좌표는 7,402개였다. 후자는 25개 구 모두에서 나왔다. 차선 종류와 관리번호를 묶은 비교가 아니므로 이 차이만으로 신규·이설·삭제를 구분할 수 없다. 대표 좌표는 최신 선형이 필요한 위치의 후보로 활용한다.

## 서울 전체 1차 대조

길이가 25cm보다 긴 유효 선형이 있는 차선 기록 339,953건을 최대 2m 간격으로 표본화했다. 표본이 차도와 보도 폴리곤 중 어디에 걸치는지 비교한 결과다. 조사한 15,723.1km는 평행 차선 표시를 각각 센 길이이므로 도로 연장을 뜻하지 않는다.

| 표본 위치 | 조사 길이 기준 비율 |
| --- | ---: |
| 차도 면에만 포함 | 88.4% |
| 차도와 보도 면에 모두 포함 | 3.8% |
| 보도 면에만 포함 | 약 0.01% |
| 두 면 밖이지만 차도에서 0.5m 이내 | 2.3% |
| 나머지 차도 밖 | 5.4% |

차도에만 포함되는 비율은 구별로 81.2~92.4%였다. 도로 층위나 방향을 가리지 않은 평면 검사여서, 교량 위 차선이 아래 차도와 겹치는 경우도 있을 수 있다. 누락 원인과 현재 차선 상태는 도로 구간별 연결과 최신 원본으로 검증한다. 기존 공개 장면의 렌더러 탈락 집계는 도로 생성·횡단 표시 절단까지 적용한 별도 지표다. [공개 장면 기준선](road-markings.md#공개-장면-전수-점검)

## 서울 전체 도로면 연결 결과

25개 구의 2021년 기본 차선과 2026년의 유효한 버스전용차로 도형을 하나의 공간 인덱스에 넣었다. 최신 버스전용차로 관리번호 3,247개 가운데 기본 차선과 일치한 3,032개를 교체하고 최신 도형의 출처를 기록했다. 인덱스에는 도로면 311,290건, 보도면 60,715건, 차선 도형 340,162개와 위치별 연결 구간 806,797개가 들어 있다.

이 단계는 원본 선형과 도로면·보도면이 실제로 만나는 위치에서 구간을 나눈다. 원래 선의 좌표와 관리번호를 유지하고 각 구간에 시작·끝 거리, 겹치는 도로면 후보, 해당 후보의 UFID를 기록한다. 단순 평면 표본 조사와 달리 연결 구간 길이를 직접 합산할 수 있다.

| 연결 상태 | 차선 길이 |
| --- | ---: |
| 보도와 겹치지 않고 도로면 하나에만 포함 | 13,633.5km (86.6%) |
| 도로면 여러 개와 겹침 | 278.2km |
| 도로면과 보도면에 모두 포함 | 599.9km |
| 보도면에만 포함 | 1.3km |
| 도로·보도면 밖 | 1,221.3km |

가락과 강서에서 원본을 다시 내려받지 않고 각각 필요한 범위의 GeoJSON을 뽑았다. 차도·보도 형상과 차선 상태를 함께 내보내 가락에서 719개, 강서에서 1,795개의 차선 조각을 검토할 수 있었다. 도로면 하나와 겹친 기록에도 방향과 높이 판단이 남아 있다. 여러 후보가 있는 곳의 차선과 원본 도형도 인덱스에 보존해 정밀도로지도와 최신 서울시 원본이 들어오면 같은 위치를 다시 대조할 수 있다.

### 가락 정문처럼 도로면이 빠진 곳

지금까지 문제가 반복된 가락 정문 황색 실선 `11-0000104759`의 30.81m 전부가 서울시 일반 도로면 범위 밖이었다. 부지안도로 원본의 양쪽 경계를 자동으로 대조하자 일곱 단면 모두에서 UFID 끝자리 216과 151인 선이 이어졌다. 두 선 사이의 간격은 약 14.9~16.1m였다. 주변 경계선을 폐합하면 이 실선을 포함하는 면이 나오지 않아, 실제 차량 포장 폭과 양끝 접속은 추가 근거로 확인해야 한다. [서울시 부지안도로 원본](https://openlab.eseoul.go.kr/qgisplugin/SHP/N1L_A0010000.zip) · [가락 정문에서 확인한 원인](road-markings.md#가락-정문에서-확인한-원인)

같은 검사를 서울 전체의 3m 이상 도로면 밖 구간 38,561개에 적용했다. 정지선을 제외하고 최대 5m 간격으로 단면을 만들었으며, 양옆 18m 안에서 동일한 원본 경계 한 쌍이 계속 확인되는 경우만 후보로 집계했다. 검사한 약 1,191km 가운데 1,156개 구간, 약 22.8km(1.9%)에서 양쪽 경계 후보를 찾았다. 후보마다 차선 관리번호와 양쪽 경계 UFID를 기록했다. 포장과 접속부가 확인되면 해당 구간을 다시 검증하고, 다른 구간은 최신 차도면과 층위 자료로 보강한다.

### 서울 전역 실폭도로 대조

브이월드에는 행정안전부의 `(도로명주소)실폭도로_서울.zip`이 서울 전체 한 파일로 올라와 있다. 2026-11 상태로 표시된 자료의 갱신일은 2026-11-13, 표시 용량은 26MB, 카탈로그 좌표계는 EPSG:5179다. 원본 다운로드에는 로그인이 필요하며 브이월드 자료 담당자는 이 레이어의 API를 제공하지 않는다고 안내한다. [실폭도로 다운로드와 데이터 문의](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=MK&dsId=30057) · [행정안전부 도로명주소 전자지도](https://www.data.go.kr/data/15050413/fileData.do)

이 자료를 확보하면 동일한 좌표계로 변환해 기존 차도·보도 둘 다 밖에 있는 차선 구간 60,713개, 약 1,221.3km를 한 번에 검사할 수 있다. 겹친 길이는 실폭도로 폴리곤 하나에 포함된 부분, 여러 폴리곤에 겹친 부분, 여전히 도로 밖인 부분으로 나눠 기록한다. 차선 관리번호에 연결되는 구간 키와 실폭도로의 파일명·레코드 번호를 보존한다. 기존 서울시 차도면을 대조군으로 입력했을 때 25개 구의 전체 길이와 가락 정문의 도로면 밖 30.81m가 그대로 재현됐다. [실폭도로 비교 코드](../../backend/scripts/compare_seoul_road_surface.py)

서울 25개 구를 대상으로 한 연구에서 2025년 10월 실폭도로의 도로 경계 꺾임점 3,768개를 항공 정사영상과 대조했을 때 평균 거리 오차는 1.87m였다. 따라서 이 레이어와 겹친다는 사실은 포장 후보의 근거로 사용한다. 차선 위치와 도로 층위는 최신 노면표시 선형과 구조물 자료로 각각 확인한 뒤 연결한다. 가락 정문을 포함한 실제 2026년 실폭도로의 수록 여부는 ZIP을 받아 검사해야 한다. [도로명주소 실폭도로 위치오차 연구](https://www.ksgpc.or.kr/jksgpc/journal/thesisPrint/Vol/1554.pdf)

같은 행정안전부 원본의 다른 확보 경로는 주소정보누리집이다. 전자지도에서 서울특별시 전체를 지정해 시·도 단위로 신청할 수 있다. 이 경로는 본인 확인과 관할 기관의 이용목적 심사를 거친다. [공공데이터포털의 도로명주소 전자지도 안내](https://www.data.go.kr/data/15050413/fileData.do)

국토지리정보원의 연속수치지형도 도로경계면도 브이월드에서 전국 묶음으로 제공한다. 2026-11-22 확인 당시 지역별 ZIP 목록은 전국 ZIP 두 개로 바뀌어 있었다. 두 파일의 표시 갱신일은 2026-10-01이고, 합계는 1,682MB다. 카탈로그 좌표계는 EPSG:5179이며 기준일은 비어 있다. 로그인 후 두 파일을 선택다운로드하는 경로이며 실제 수록 범위와 관측일은 ZIP을 열어 확인한다. [브이월드 연속수치지형도 도로경계면](https://www.vworld.kr/dtmk/dtmk_ntads_s002.do?svcCde=MK&dsId=30179)

### 서울시 도로·도로시설물 공간정보와 수치지형도

서울시는 2021~2025년에 서울 전역 1:1,000 수치지형도를 갱신했다고 안내한다. 시가 운영하는 기본도는 도엽을 지형지물별로 이은 연속수치지도다. 서울시의회 자료에는 도로 관련 시스템이 시·구 도로의 도로면·보도면·도로중심선과 고가차도·입체교차·교량·터널·지하차도 등의 공간정보를 관리한다고 나와 있다. 기존 오픈랩 파일의 SHP 색인 날짜는 2024-07-04이므로, 서울시 공간정보과와 도로관리 부서에 전역의 최신 연속 레이어와 관측·갱신 범위를 묶어서 요청한다. 내부 데이터의 제공 가능 여부와 최신 기준일은 담당 부서 회신으로 확인한다. [서울시 수치지형도 안내](https://news.seoul.go.kr/gov/archives/528208) · [서울시의회 도로정보화시스템 자료](https://ms.smc.seoul.kr/attach/record/SEOUL/appendix/a11/A0065782.pdf)

국토정보플랫폼에는 서울시의 공개 1:1,000 수치지형도 2.0을 로그인 후 도엽 단위로 받는 경로도 있다. 공개 포털의 지도 정보 이력 CSV는 설명에 여러 축척을 열거하지만 실제 내려받은 `20250828` 파일 27,015행은 모두 1:5,000이었다. 서울 1:1,000 최신 도엽이나 갱신 범위는 이 CSV로 확인할 수 없다. 별도로 국토지리정보원의 **기본공간정보**는 서울 행정구역 전체를 한 번에 지정해 도로경계면·경계선·교량·입체부·램프·터널을 선택할 수 있다. 이 자료는 1:5,000이며 도로면과 구조물의 보조 대조에 쓴다. [지도 정보 이력](https://www.data.go.kr/data/15148179/fileData.do) · [수치지도 2.0](https://www.data.go.kr/data/15059719/fileData.do) · [기본공간정보](https://www.data.go.kr/data/15059910/fileData.do)

## 서울 전체 도로중심선·입체도로 검사

위 인덱스의 806,797개 구간을 서울시 에스맵 도로중심선과 대조했다. 차선이 도로면 하나와 겹치는 부분을 최대 4m 간격으로 검사했다. 16m 안에서 같은 도로면 위의 중심선을 찾고, 진행 축과 25° 이내로 나란한지 확인했다. 정지선은 중심선과 직각에 가까운지 봤다. 서로 다른 중심선의 거리 차가 1m 이내면 여러 후보로 남겼다. 원본 차선 좌표, 중심선 UFID와 분류별 길이를 저장했다.

| 표본별 판정 | 차선 길이 | 전체 차선 길이 기준 |
| --- | ---: | ---: |
| 같은 도로면에서 방향이 맞는 중심선 후보 하나 | 11,619.0km | 73.8% |
| 중심선 후보 여러 개 | 1,170.0km | 7.4% |
| 같은 도로면에서 조건에 맞는 중심선 없음 | 844.5km | 5.4% |
| 도로면을 하나로 특정하지 못함 | 2,100.7km | 13.4% |

첫 항목은 구별로 64.8~80.3%였다. 한 구간 안에서도 위치마다 다른 중심선이 후보가 될 수 있다. 이 비율은 기존 차선 도형이 도로면과 진행 축에 맞는 정도를 보여준다. 차선 설치 시점, 차량 통행 방향, 동일한 구조물 위에 있는지는 별도 근거로 확인한다.

일반도로의 표준노드링크와 입체도로의 링크가 둘 다 16m 안에 있는 표본은 전체 차선 길이 중 981.8km(6.2%)였고, 25개 구 모두에서 찾았다. 가락 정문의 30.81m는 전체가 도로면 미확정으로 유지됐다. 검수에서 구조가 가까이 잡히면 해당 링크 ID와 구조 종류를 남기고, 배포 전에 어느 차도에 붙이는지 별도 도형으로 확인한다. 링크 검색은 평면 거리 기준이므로 구조 링크가 보이지 않는 곳도 실제 높이는 추가 자료로 확인한다. 링크가 표현하는 교통망을 차선 좌표나 도로 높이로 변환하지 않는다. [국가교통정보센터 표준노드링크 자료실](https://www.its.go.kr/nodelink/nodelinkRef) · [국토교통부 표준 노드·링크 구축기준](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulId=32722&efYd=0)

### 차선 자료가 없는 도로도 점검

차선 파일에 레코드가 없는 도로는 차선에서 출발하는 검사로 찾을 수 없다. 2026-11-11 표준노드링크의 서울 25개 구 사용 중인 도로 링크 62,575개를 출발점으로 같은 자료를 다시 대조했다. 링크를 최대 4m 간격으로 표본화했다. 한 차도면 안에서 16m 이내에 있고 진행 축과 25° 이내로 나란하며 표본에서 내린 수선이 실제 선형에 닿을 때만 후보로 센다. 보도와 겹치는 표본은 차도면 미확정으로 분류했고 정지선은 검사에서 제외했다.

| 도로 링크에서 본 상태 | 방향별 링크 길이 |
| --- | ---: |
| 같은 차도면에서 차선 후보 발견 | 3,110.9km |
| 차도면을 특정했으나 차선 후보 없음 | 626.2km |
| 차도면을 하나로 특정할 수 없음 | 2,151.6km |

차도면이 특정돼도 차선 후보가 없는 구간은 25개 구 모두에 있다. 전체 길이에서 후보가 한 번도 잡히지 않은 링크는 20,693개다. 이 중 차로가 두 개 이상이고 표준링크가 2024년 1월 1일 이후 갱신된 2,777개부터 최신 노면표시와 차도면에 대조할 수 있다. 링크 갱신일은 도색일과 별개다. 5,888.7km는 양방향 링크를 각각 집계한 길이다. 표준노드링크에 없는 골목과 부지 내 도로는 서울시 연속수치지도와 별도로 대조한다. 후보는 같은 차도면 안에 나란한 표시가 있음을 뜻하며 모든 차로의 도색 또는 현재 현장과의 일치 여부는 따로 확인한다. [표준노드링크 자료실](https://www.its.go.kr/nodelink/nodelinkRef) · [도로 링크 기준 점검 코드](../../backend/scripts/audit_seoul_link_coverage.py)

### 2026년 교차로별 차로 경로를 한 번에 확보

서울 교통빅데이터에서 교차로 기준점, 차로 속성, 차로 노드 CSV 세 개를 로그인과 API 키 없이 받았다. 노드의 등록일은 2026-10-20이다. 교차로 ID와 차로 ID로 연결하고, J2735의 cm 단위 동쪽·북쪽 오프셋을 노드 순서대로 합산해 WGS84 기준점에서 경로를 복원했다. 도로면과 대조할 때는 EPSG:5186을 사용했다. 이 도형은 차량이 지나는 차로 중심 경로다. 도색된 실선·점선의 위치와 유형은 노면표시 선형에서 별도로 확인한다. [교차로 MAP](https://t-data.seoul.go.kr/dataprovide/trafficdataviewfile.do?data_id=10144) · [차로 MAP](https://t-data.seoul.go.kr/dataprovide/trafficdataviewfile.do?data_id=10145) · [노드 MAP](https://t-data.seoul.go.kr/dataprovide/trafficdataviewfile.do?data_id=10147) · [SAE J2735](https://webstore.ansi.org/preview-pages/SAE/preview_J2735_202409.pdf)

서울시 자치구 경계로 판정한 결과 25개 구 **교차로 2,547곳, 차로 경로 41,902개**를 복원했다. 교차로 기준점 38건은 서울 경계 밖이거나 구를 하나로 특정할 수 없었고, 연결 조건을 통과한 데이터 중에서도 노드 순서가 연속되지 않은 차로 4,832개는 경로 생성에서 제외했다. 생성된 경로를 최대 4m 간격으로 대조했더니 길이의 **94.65%가 기존 차도면과 겹쳤고, 약 356.3km는 차도·보도 모두 밖**에 있었다. 교차로 사이에서 서로 겹치는 경로도 각각 센 수치다. 차도 밖에 있는 곳은 최신 차도 경계·구조물과 대조할 후보로 남긴다. 등록일은 측량일과 별개다. 교차로 기준 자료이므로 골목과 단지 안쪽의 수록 범위는 별도로 확인한다. [서울시 자치구 경계](https://data.seoul.go.kr/opendata/seoulStay/grid_viewer.html) · [일괄 수집·대조 코드](../../backend/scripts/audit_seoul_cits_lanes.py)

송파구 39개 구간에는 송이로와 중대로1·2길이 있다. 가락 정문 주소의 송파대로32길은 구간 이름 목록에서 확인되지 않았다. 구간 이름은 여러 도로를 묶기도 하며, 464개 구간의 거리 항목은 0으로 반환되어 목록에서 도로 길이 비율을 계산할 수 없었다. 파일 선택 화면의 ID와 구축현황의 연도도 따로 기록했다. 실제 SHP의 수록 경계, 측량일과 노면표시의 높이까지는 로그인 후 받은 파일에서 확인한다.

2. 받은 묶음에서 노면선표시와 도로 연결 도형을 읽고, 실제 포함 범위·측량일·좌표계·높이 기준을 확인한다. 앞의 서울시 차선 인덱스와 대조해 범위 안에서 증거가 있는 도형을 갱신한다. 권역에 걸친 도로는 원본 구간 ID를 따라 중복을 제거한다. [정밀도로지도 제공 항목과 공공누리 조건](https://www.data.go.kr/data/15059912/fileData.do)
3. 서울시 T-GIS를 기본으로 사용하고 표준노드링크에서 확인된 누락, 입체교차, 진행 방향 미확정 구간을 정밀도로지도와 대조한다. 두 원본에서 모두 확인하지 못한 위치는 범위와 이유를 남긴다. 공동주택 부지 도로는 부지안도로 경계와 근거를 대조한다.

## 수작업을 줄이는 생성 방식

1. **도시 단위 스냅샷을 먼저 만든다.** 위 파일을 한 캐시에 받고 버전·해시를 기록한다. 보도, 차도, 횡단보도, 중심선, 차선을 도시 공통의 공간 인덱스에 넣고, 배포할 때만 같은 범위의 타일로 자른다. 같은 도로가 여러 단지에 걸려도 한 번 연결한다.
2. **차선을 실제 차도에 연결한 뒤 3D를 만든다.** 차도 폴리곤과 중심선의 관계를 먼저 만들고 도로 구간, 방향, 층위, 차도 경계를 저장한다. 실선 등 길이 방향 표시는 연속으로 겹치는 길이·방향·옆 차도와의 분리 여부로 연결한다. 정지선과 횡단보도는 교차로·진입로의 가로 방향과 경계를 대조한다. 원본의 차선 선형을 보존하고, 접속부의 차도 면만 동일한 근거의 경계에 맞춘다. 다른 층에 겹치거나 후보 도로가 여럿이면 미확정으로 남긴다.
3. **원본 관리번호는 갱신에 쓴다.** 2021년 유효 차선 모두에 `MGRNU`가 있고 `SIXID`는 200,496건에 있다. 도로명 코드 `RN_CDE`는 이 파일의 유효 레코드에서 비어 있다. 관리번호가 같은 최신 레코드는 병합 후보로 사용하고, 한 번호에 여러 조각이 있으면 도형과 범위를 함께 비교한다. 도로 면은 별도 `UFID`를 가지므로 차선 식별자만으로 도로에 연결할 수 없다.
4. **수집 범위에 없는 도로와 층위를 보완한다.** T-GIS 시민용 지도 스냅샷으로 전체를 먼저 수집한다. 원본의 구간·층위 ID, 측량 기준일, 공동주택 부지 내부의 수록 범위, 웹서비스 제공 조건처럼 자료에 드러나지 않은 항목은 서울시에서 확인한다. 국토지리정보원 정밀도로지도는 확인된 수록 구간의 도형과 높이 검증에 쓴다. [서울시 공공데이터 제공신청](https://data.seoul.go.kr/etc/offerReqst.do) · [국토지리정보원 공개 구축현황](https://map.ngii.go.kr/ms/map/NlipMap.do)
5. **자동 검수 후 근거가 있는 구간을 배포한다.** 출처가 확인된 차선, 원본에서 차선 없음이 확인된 도로, 미수집·불일치 도로를 각각 기록한다. 차선이 잘렸거나 보도·다른 층으로 간 위치를 목록으로 남겨 최신 자료와 대조한다. 공개 타일의 차도와 도색은 같은 구간 연결 결과에서 생성한다. [상세 배포 기준](road-markings.md#배포-전-점검-기준)

서울시에 전달할 요청 내용

> 서울 25개 구의 T-GIS 차선·정지선(`A058_L`)과 횡단보도·노면표시 전체 선형 최신 원본을 GeoPackage 또는 SHP로 받을 수 있는지 확인 요청드립니다. 공개된 2021년 선형에는 이후 변경 내용을 확인하기 어렵습니다. 관리번호, 분류코드, 도로·교차로 연결키, 방향·층위, 설치·변경일, 삭제 이력 또는 변경분, 측량 범위와 좌표계가 필요합니다. 자료는 실제 도로와 보행환경을 보여주는 온라인 3D 임장에 사용합니다. 웹 타일로 가공해 공개 서비스로 제공할 때의 이용 조건도 함께 안내 부탁드립니다.

> 서울 25개 구의 최신 1:1,000 연속수치지도 또는 도로관리시스템에서 관리하는 도로면·보도면·도로중심선, 입체교차·램프·고가차도·교량·터널·지하차도 공간 레이어를 묶어서 받을 수 있는지 확인 요청드립니다. 부지안도로와 공동주택 진입로의 수록 범위, 도형별 식별자와 구조물 연결키, 좌표계와 높이의 기준, 촬영·조사·갱신 기준일과 제외 구간도 필요합니다. 공개 공간 레이어의 가공 및 온라인 제공 조건을 함께 안내 부탁드립니다.

## 공개 장면 일괄 갱신

서울 10개 장면의 차선 23,950개를 기존 기준 범위와 2021년 원본으로 재현했다. 이어 서울 전체 인덱스에서 2026년 버스전용차로를 반영한 차선을 읽고 같은 범위로 잘랐다. 이렇게 10개 장면에 **관리번호 191개, 장면별 중복을 포함해 252개 선형 조각**을 연결했다. 횡단보도, 감속 표시, 보도 자료는 이번 갱신의 비교 기준으로 사용했다. 2026년 버스전용차로 ZIP 공개일은 2월 13일이고 ZIP 안의 SHP 색인 파일 날짜는 2월 12일이다. 장면별 JSON에 ZIP 해시, 적용한 출처와 범위, 갱신 선형의 관리번호를 기록했다. [서울시 버스전용차로 위치](https://data.seoul.go.kr/dataList/OA-22396/F/1/datasetView.do)

청색 실선·점선·복선은 서울시 차선 유형 코드로 구분한다. 점선의 도색과 빈 간격은 경찰청 규격을 따라 3m씩 모델링했다. 겹치는 장면에서 점선이 다른 위치로 옮겨 보이는 일을 줄이기 위해, 잘린 첫 좌표가 원본 선의 시작점에서 얼마나 떨어져 있는지도 전달한다. 두 줄로 된 점선은 같은 시작 위치에서 나눈다. 원본에는 개별 도색 조각의 길이·시작점이 따로 들어 있지 않다. [서울시 차선 정의서](https://data.seoul.go.kr/dataList/OA-15537/S/1/datasetView.do) · [경찰청 교통노면표시 업무편람](https://itskorea.kr/downloadFile.do?fileId=FILE_000000000038775&fileSn=2)

## 재현 명령

Python 3.11 이상에서 실행한다. 작업 폴더의 `road-source-cache`에는 원본을 저장하고, 결과 JSON에는 자치구별 거리 합계, 도형 개수, CRS, 파일 해시와 번호 일치 건수를 남긴다. 기본 실행은 캐시만 사용하고 `--download`를 붙이면 누락된 원본도 받는다.
