송파의 기존 4곳에 마포·성동·성북에서 각각 두 곳을 더했다. 마포는 한강 인근, 성동은 청계천 인근, 성북은 지형 고저차가 큰 생활권으로 골랐다. 각 생활권에서 두 단지가 지도 원본 하나를 공유하도록 설정했다. 새 6곳의 건물 재질과 경관은 공통 렌더링 규칙을 사용한다.

공개 지도 단지 경계에 주동 중심점이 모두 들어가는지, 같은 건축물대장 자료의 인접 단지 주동이 섞이지 않았는지 확인했다. 주동 윤곽 면적이 경계에 포함되는 비율은 래미안길음1차의 한 동에서 최소 94.3%였다. 수치는 지도의 경계 정합성을 점검한 것으로, 법적 필지 경계와 실제 출입구 위치는 별도 자료로 확인해야 한다. [건물 원본과 연결 규칙](2026-11-21-seoul-tour-coverage.md#주동을-지도-윤곽에-연결) · [GEDTM30 지형 원본](https://zenodo.org/records/15689805)

같은 생활권의 두 단지는 도로·환경·생활시설·지형 파일을 동일한 URL에서 읽는다. 도로·환경·생활시설 파일을 두 벌 저장할 때에 비해 세 생활권에서 약 6.8MB의 비압축 데이터 중복을 줄였다. 건물은 단지별 범위로 내보내고, 각 범위가 공유 지형 안에 들어오는지 검사한다. 단지 경계를 넘어 다른 장면으로 이어서 걷는 기능은 후속 검증 항목이다.

도로면과 보도면, 차선, 횡단보도와 보행 신호 개체는 서울시 자료를 같은 방법으로 결합했다. 길음 보도면의 접점에서 정밀도 반올림으로 생긴 작은 잘못된 도형은 공통 전처리에서 복구하고 면 도형만 남겨 도로를 자른다. 신호등은 디지털 관리대장의 설치 기록과 지주 좌표가 연결된 곳에 표시한다. 현재 신호 주기·가동 상태는 현장에서 확인해야 한다. ## 이웃 단지의 지형 높이 대조

이전에는 같은 지형 원본을 단지 중심마다 별도의 25m 격자로 보간했다. 두 단지의 반경 600m가 겹치는 구역에서 20m 간격으로 같은 절대 좌표를 대조한 결과, 렌더링에 사용되는 삼각면의 높이는 아래와 같이 달랐다. 이제 생활권 지도 범위의 가운데를 EPSG:5186의 25m 격자에 맞추고, 그 원점과 표고 격자를 두 장면이 함께 쓴다.

| 생활권 | 대조 좌표 | 이전 지면 높이 차이 최댓값 | 공유 후 최댓값 |
| --- | ---: | ---: | ---: |
| 마포 용강 | 2,379 | 1.45m | 0m |
| 성동 청계천 | 1,580 | 1.67m | 0m |
| 성북 길음 | 1,146 | 1.49m | 0m |

실제 장면 로더와 지형 삼각망을 사용해 두 앱 장면의 같은 절대 좌표를 비교했다. 5,105개 대조 좌표의 모델 표고와 삼각면 높이가 같았고, 각 쌍의 지형 정점과 법선 배열도 일치했다. 일조와 시야에서 건물 자료가 충분한 범위, 주변 시설 거리의 단지 기준점은 각각의 단지 중심에 유지했다. 이 대조는 장면 간 정합성만 확인하며, 보도·연석의 실제 높이는 원본 해상도로 판정하기 어렵다.

`osm.neighborhood`를 지정한 단지에는 `node frontend/scripts/prepare-opo-terrain.mjs --region <지역 ID>`를 생활권당 한 번 실행한다. 결과는 `frontend/public/datasets/neighborhoods/<생활권>/terrain.json`에 저장된다. `prepare-region.mjs`로 같은 생활권의 단지 전체를 검사한다.

## 재생성

1. `data/config/buildings/seoul-a*.json`에서 대상 코드와 `osm.bounds`를 가져온다. 세 생활권별 OSM 스냅샷을 받아 같은 생활권의 두 단지에 전달한다. 공개 API는 갱신되므로 당시 파일을 재현하려면 아래 해시의 원본이 필요하다. [OSM 범위 API](https://wiki.openstreetmap.org/wiki/API_v0.6)
2. `prepare_seoul_building_windows.py`에 6개 `--complex`를 한 번에 넘기고 각 결과의 `config.json`으로 `python -m backend.pipeline build-geojson`을 실행한다. `prepare-catalog-scene.mjs`에 단지 ID, 건물 창 폴더와 해당 생활권 스냅샷을 전달한다. [기존 생성 명령과 자료](2026-11-21-seoul-tour-coverage.md#주동을-지도-윤곽에-연결)
3. 단지 경계 400m 범위에 `prepare_neighborhood_pavement.py`와 `collect_seoul_pedestrian_signals.py`를 적용한다. 중심 좌표에서 경도 ±0.009°, 위도 ±0.0075° 범위로 `prepare_songpa_road_markings.py`를 실행한다. [차선·보도·신호 생성 명령](2026-11-21-jamsil-leel-build.md)
4. `walking`이 들어 있는 세 단지에 `prepare_catalog_walks.py --retrieved 2026-11-21`과 `prepare_songpa_route_elevation.py --region`을 실행한다. `prepare-catalog-scene.mjs`를 재실행해 생성한 레이어를 인식시킨 뒤 `audit_seoul_tour_coverage.py --public-output`으로 공개 목록을 갱신한다. [보행 경로와 목록 생성 명령](2026-11-21-seoul-tour-coverage.md#역공원-보행-경로와-서울-목록)
